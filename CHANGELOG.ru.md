## [1.3.2] - 2026-10-17

- AmneziaWG на сервере без `ufw`: служба `deploy/awg-forward.service` (systemd) добавляет в цепочку `DOCKER-USER` разрешения пересылки для интерфейсов туннелей после каждого запуска Docker (политика пересылки Docker — `DROP`). Случай описан в `AMNEZIAWG.ru.md`; с `ufw` установщик по-прежнему добавляет правила сам.

## [1.3.1] - 2026-10-17

- Telemt (MTProto) обновляется из панели и за пределами образа: экран «Версии» предлагает выпуски апстрима (`telemt/telemt`), которых ещё нет в образе `mtproxymax-telemt`. Агент версий скачивает бинарь, сверяет SHA-256 из метаданных выпуска GitHub, собирает на хосте образ поверх закреплённого базового образа и переключает `mtproxy` на него; при сбое возвращается предыдущее состояние. Сейчас так доступна версия 3.5.14.

## [1.3.0] - 2026-10-17

- Протокол **AmneziaWG** (необязательный): VPN поверх UDP — WireGuard с маскировкой трафика. Версии **1.5, 2.0 и 3.1** работают одновременно, каждая на своём интерфейсе, UDP-порту и подсети узла (по умолчанию 51820, 51821, 51822), потому что версии несовместимы между собой. Версию выбирают по каждому клиенту: в матрице «Узлы и доступы» появились колонки «AmneziaWG 1.5 / 2.0 / 3.1», у клиента может быть несколько версий сразу. Конфиг выдаётся файлом `.conf` и QR из окна доступа и не входит в подписки. Закрытый ключ клиента хранит панель, узел получает только открытый; ротация выпускает новую пару ключей. Устройство, включение и диагностика — в `AMNEZIAWG.ru.md`.
- Менеджер узла `awg-manager` (контейнер на `amneziawg-go`, собранном из закреплённого коммита) и раздел `[amneziawg]` установщика: `enabled`, `versions`, `host`, порты, MTU, DNS. Установщик включает пересылку IPv4, открывает UDP-порты и разрешает пересылку для интерфейсов туннеля в брандмауэре, которым управляет. Новый домен не нужен: подойдёт имя панели, если оно указывает прямо на сервер.
- Панель: карточка AmneziaWG на обзоре, состояние в списке узлов, инструменты MCP и навык принимают версию (`options.version`), панель отказывает сразу, если узел не обслуживает выбранную версию.
- Миграция базы 23 расширяет список протоколов в `access_grants`; узлы получают её тем же обновлением. Узлы старее 1.3 не получают ресурсов AmneziaWG (возможность `protocol.amneziawg.v1`).
- Исправлено: версионный агент снова может обновлять NaiveProxy (Caddy) — его песочнице не хватало записи в `/var/log/caddy`, из-за чего проверка конфигурации и откат завершались ошибкой.

## [1.2.1] - 2026-10-17

- Обновлены закреплённые компоненты: Xray 26.10.17 (последняя бета), Mieru/mita 3.38.1, Caddy 2.11.7 (сборка Naive и пограничный Caddy), 3x-ui 3.10.2 для режима `managed-new`, образ MTProto (Telemt) 3.5.9. ## [1.2.0] - 2026-10-17

- Клиента можно переименовать (`POST /api/clients/{client_id}/rename`, кнопка «Переименовать» на карточке клиента), а любому доступу задать своё название в подписках (`POST /api/clients/grants/{grant_id}/label`, окно доступа → «Название в подписке»; пустое название возвращает «узел · протокол»). Своё название действует в sing-box/Throne, Clash, HTML и `raw`; учётные записи, адреса, секреты и ссылка подписки не меняются, условные запросы сразу видят новые имена. Переименование узла на экране «Узлы» работало и раньше, оно не изменилось.
- Миграция базы 22 добавляет `access_grants.label`; узлы получают её тем же обновлением, протокол Fleet и публичный манифест v1 не меняются. В журнале появились записи `client.rename` и `grant.label`.

## [1.1.4] - 2026-10-12

- Один запрос выдаёт любое число доступов: лимит в 8 доступов снят, поэтому «все протоколы на всех узлах» больше не заканчивается ошибкой 422 и клиентом без доступов.
- Список клиентов сам перечитывается, пока какой-либо доступ ждёт узел: «ожидает узел» пропадает, когда узел подтвердил, а не висит до перезагрузки страницы.

## [1.1.3] - 2026-10-11

- Подписки различают подключения с разных узлов: имя узла и протокол вместо одного логина. Совпадающие названия получают стабильный суффикс; Mieru сохраняет различие транспорта и порта. Общие правила действуют для sing-box/Throne, Clash, HTML и подписей Naive/Mieru в raw. Переименование узла обновляет ETag без смены ссылки подписки или учётных данных.

## [1.1.2] - 2026-10-04

- `uninstall` без `--purge-data` снимает пакеты, которые поставил установщик, `apt-get remove` вместо `apt-get purge`: `/var/lib/docker` со всеми томами (включая базу панели) и `/etc/letsencrypt` от certbot остаются. Purge выполняется только при явном `uninstall --purge-data`; откат неудачной установки снимает пакеты, но не делает purge. То же правило действует для рантайма `proxyctl`.
- Чтение статуса пакетов принимает вычищенный пакет, который dpkg хранит с пустой версией; раньше `uninstall` падал сразу после purge.
- Отказы маршрутизации в панели и API называют, какой возможности не хватает узлу, вместо старого номера версии; сценарий обновления и `install-release.sh --requirements` больше не ссылаются на бета-выпуски.
- README переписан с отдельными разделами установки для человека и для ИИ-агента; документация описывает текущее поведение, история до 1.0.0 удалена.

## [1.1.1] - 2026-10-03

- Включает исправления жизненного цикла клиентов, ограниченной параллельности Fleet, отката обновления и штатного установщика из неопубликованных кандидатов rc.1–rc.3 ниже.

Управляемая установка удаляет временные проверочные аккаунты через API клиентов: 3x-ui 3.9 больше не меняет клиентов через обновление инбаунда. - Клиенты управляемого Hysteria2 создаются с явным признаком включения. Без него 3x-ui хранит аккаунт в API, но не включает его в работающую конфигурацию Xray.
- Явный purge управляемого 3x-ui после остановки службы удаляет также служебные файлы SQLite и кэш метрик, сохраняя неизвестные файлы. Свежая установка отказывается использовать оставшийся каталог базы.

## [1.1.1-rc.3] - 2026-10-03

Неопубликованный кандидат с проверкой штатным установщиком на нативном сервере.

- Обновление панели передаёт установщику владение кодом Core и version-agent под общей блокировкой. Для первого перехода со старым агентом доступно согласование с точным архивом. Изменение только installer тоже перезапускает агент, обновляя импортированные модули Python.
- Неполный набор Compose overlays отклоняется до изменения работающих служб. Диагностика готовности с аутентификацией отличает ожидающее согласование от доступности процесса.
- Явный purge установщика удаляет пустой каталог обновлятора и проверенные тома Unix-сокетов менеджеров, позволяя чистую переустановку. Чужие файлы, символические ссылки и тома защищены.
- Скрипт установки выпуска и двуязычные руководства описывают согласование после старого агента. Доказательства update/repair, чистой установки/repair и повторного install записаны отдельно; публичный выпуск не создавался.

## [1.1.1-rc.1] - 2026-10-02

Неопубликованный кандидат по итогам аудита; результаты проверок фиксируются отдельно от списка изменений.

- Приостановка клиента и сроки действия доступов применяются к локальным сервисам и удалённым узлам; согласование проверяет фактическое состояние и повторяет неудачные операции. Устаревший отчёт Fleet не подтверждает ожидающую блокировку.
- Список клиентов использует пакетные запросы, серверные страницы и поиск. Число одновременных отправок Fleet ограничено; DNS проверяется при соединении с сохранением проверки имени TLS и явного разрешения приватных адресов.
- Обновление панели останавливает писателей базы перед копированием и восстановлением, сохраняет исходный WAL при неполной резервной копии и включает MCP в синхронизацию и пересборку.
- Размер тела HTTP-запроса ограничивается во время чтения; контекстные менеджеры SQLite закрывают соединения. Обновлены FastAPI, Starlette и связанные зависимости по результатам проверки уязвимостей.
- Свежая установка сохраняет IP клиента через доверенный Unix-сокет. Обновление хоста мигрирует только известные собственные шаблоны Nginx с откатом и проверкой нового поколения workers; чужой фронтенд coexist требует операторского моста.
- CI проверяет все поставляемые Compose-профили, синтаксис JavaScript, закреплённые зависимости и воспроизводимость скрипта установки.

## [1.1.0] - 2026-10-01

- Маршрутизация MTProxy: MTProxy подключается к Xray-router узла и выходит через WARP, свой выход или другой узел парка (цепь); правила по CIDR, `geoip` и порту, а правила по домену, `geosite` и протоколу — `rule_kind_unsupported` (Telemt ходит к DC Telegram по IP). Своя политика Telemt (`mtproxy_native`) — только «напрямую».
- Подключение и отключение меняют upstream Telemt через его API (`PATCH /v1/config` + `POST /v1/system/reload`) без перезапуска контейнера; журнал для отката — `/data/telemt-egress.json` панели, без секретов.
- Xray-router: третий вход `mtproxy` — VLESS на Unix-сокете; мост `xray-router-ingress` (тот же образ) в сети Compose принимает SOCKS5 Telemt на `:45103`; учётку роутер создаёт сам; исключение из обхода только на этом входе — приватные сети `:443` напрямую (TLS-фронт `mask`). `GET /v1/ingress/mtproxy`.
- Парк: ёмкость `egress.mtproxy.v1`, секция `egress.mtproxy` поколения; новые коды `router_lacks_mtproxy`, `ingress_unreachable`, `node_lacks_mtproxy_egress`, `telemt_api_unsupported`, `egress_reload_failed`.
- Миграция 21 (`routing-mtproxy`): `routing_policies` и `managed_egress` допускают `mtproxy`/`mtproxy_native`.
- Установщик поднимает, проверяет и снимает мост вместе с роутером; текст вопроса мастера и `--requirements` упоминают MTProxy.
- Обновление одной командой: `bash install-release.sh --update` проверяет выпуск, затем `scripts/update-host.sh` (root) просит version-agent обновить панель ровно до проверенного digest и пересобирает менеджеры из `pending_rebuild` (и мост роутера).

Заметка: [docs/releases/v1.1.0.md](docs/releases/v1.1.0.md).

## [1.0.3] - 2026-10-01

- Выпуск публикует `install-release.sh` и `install-release.sh.sha256`: скрипт установки с записанными версией и SHA-256 архива своего выпуска (подменённый архив не пройдёт и при подменённом `SHA256SUMS`), с attestation; `SHA256SUMS` по-прежнему называет три файла.
- Мастер установки: пояснения и значения по умолчанию у режима сервера, профиля и режима 3x-ui; порты Mieru по умолчанию `46001`; версия Xray в вопросе — из манифеста внешних артефактов; ошибка конфигурации называет причину; сводка без неиспользуемых полей.
- Исправлено: при «apply» прямо из мастера введённые пароли панели и 3x-ui заменялись сгенерированными — теперь они передаются установке во временной приватной копии.
- Исправлено: вопрос `initial_user` назван честно (первый пользователь MTProxy и Mieru; логин в панель всегда `owner`); «Домены WARP» больше не обещают «пусто — нет» и принимают `geosite:`/`domain:`; `managed-new` не предлагается в `coexist`; в `existing` спрашиваются только домены VLESS (хотя бы один); TCP-порты Mieru проверяются против портов самого установщика (8443, 8445, 8787, 4443, 8793, WARP, Xray-router, relay, слоты, управляемый 3x-ui); «Изменения не внесены» печатается один раз; логин 3x-ui сохраняется и при сгенерированном пароле; домен подписки 3x-ui — в проверке уникальности SNI.

Панель не менялась. Заметка: [docs/releases/v1.0.3.md](docs/releases/v1.0.3.md).

## [1.0.1] - 2026-09-29

- Экран «Версии»: в выпадающем списке каждого компонента несколько последних выпусков в обе стороны (новее / откат, флаг агента `newer`); панель предлагается только вперёд, откат панели агент отклоняет. То же на вкладке «Обновления» узла.
- Mieru принимает любую mita: списка проверенных линий больше нет. Менеджер пишет конфигурацию целиком командой, которую знает бинарь (`replace config` с 3.38, `apply config` раньше), читает каждую запись обратно и откатывает при расхождении; откат, не вернувший снимок, помечается как требующий восстановления.
- Geodata: региональные источники «runetfreedom» (Россия), «iran» (chocolate4u) и «v2fly» рядом с Loyalsoldier и пином; новый роутер сразу берёт Loyalsoldier с ежедневным обновлением, нетронутый пин переходит туда при обновлении. Ежедневное обновление ждёт `update_hour` (UTC, по умолчанию 02:00); в строке видно последнюю и следующую проверку. Файлы до 128 МБ (российский geosite ~74 МБ); ошибка перезапуска после подмены записывается; пин следует за новым архивом Xray; скачивание — вне потока watchdog.
- Исправлено: проверка обновлений NaiveProxy запрашивала ветку forwardproxy `caddy2`, которой больше нет (422); теперь берётся ветка `naive`.
- Быстрые настройки маршрутизации «Заблокированное в РФ → через WARP» (нужен источник runetfreedom), «Китайские домены и IP → напрямую», «Иранские домены и IP → напрямую»; два новых сценария инструкции.

После обновления панели пересоберите `mieru-manager` и `xray-router`. Заметка: [docs/releases/v1.0.1.md](docs/releases/v1.0.1.md).

## [1.0.0] - 2026-09-28

Первый стабильный выпуск: сохранённые ключи Mieru, подписка для Throne, пошаговая маршрутизация со встроенной инструкцией и английский интерфейс.

- Маршрутизация стала пошаговой: для кого → куда идёт трафик → проверить → применить на узле, у каждого шага короткое пояснение. Возможности сервиса названы словами вместо кодов, выходы, Xray-router, списки geosite/geoip и relay собраны в сворачиваемый блок «Возможности узла», технические детали проверки свёрнуты под человеческой сводкой черновика.
- «Как это работает» — подробная инструкция прямо в панели: термины, что умеет каждый сервис, восемь пошаговых сценариев с кнопкой «Начать» (весь трафик через WARP, отдельные сайты через WARP, реклама, торренты, российские сайты напрямую, цепь через другой узел, свой выход, отдельный маршрут клиенту), разница между «Сохранить» и «Применить», что делать, если проверка говорит «не применимо». Сценарий только готовит черновик — на узел ничего не уходит без «Сохранить» и «Применить».
- Английский интерфейс: переключатель RU/EN в шапке и на странице входа, выбор запоминается в браузере. Переведены все экраны, диалоги и уведомления; даты и числа — в формате выбранного языка.

- Ключи Mieru больше не нужно ротировать, чтобы показать снова: панель хранит каждый выданный ею ключ в зашифрованном хранилище, а кнопка «Конфигурация» на странице Mieru показывает текущий ключ без изменений на узле (`POST /api/mieru/users/{username}/access`). Пользователи, выданные раньше, помечены «Ключ не сохранён» — после одного «Новый ключ» ключ сохраняется. Кнопка «Новая ссылка + QR» переименована в «Новый ключ».
- Исправлено: создание и ротация на страницах Mieru и NaiveProxy шли мимо хранилища панели, и подписка клиента продолжала отдавать заменённый пароль. Теперь новый пароль сразу попадает в подписку.
- Throne (бывший Nekoray): проверен на Throne 1.3.1. Он берёт NaiveProxy и Mieru из варианта «sing-box JSON для Karing и Throne»; Clash YAML Throne не импортирует вовсе. В окне клиента и в матрице совместимости это теперь написано; у доступов появилась отметка `throne`. Ограничение Throne 1.3.1: Mieru по UDP подключается, только если сервер указан IP-адресом.
- Карточка клиента: доступы выстроены таблицей с общими колонками (протокол · аккаунт · состояние · маршрут · действия), в одном порядке MTProxy → Naive → Mieru, с цветной точкой состояния; на телефоне — аккуратные карточки. Архивные клиенты идут в конце списка. Кнопка маршрута называет действие («Выделить полосу» / «Вернуть общий»).
- Обзор: заглушка при загрузке повторяет настоящую раскладку (ресурсы сервера и три карточки протоколов) — плитки больше не прыгают между 3 и 4. В строке «Оперативная память» показывается swap (нужен агент хоста из этого выпуска).
- Акцентный цвет: кнопка-палитра в шапке, семь вариантов, выбор хранится в браузере.
