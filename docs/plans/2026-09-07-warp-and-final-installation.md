# Доведение установки и автоматический WARP

Рабочий план. Написан 2026-09-07 по ходу настоящей установки на одноразовом
сервере `ams-test` (`89.124.96.226`). Содержит состояние, добытые факты и
задачи — так, чтобы работу можно было продолжить в новом контексте без
повторного расследования.

## 1. Где остановились

Установка профиля `full` с `three_xui.mode = "managed-new"` доходит до
**8 действий из 12** и откатывается на приёмке MTProxy:

```
AcceptanceError: Core acceptance failed: resPQ:
probe: MTProto proxy verification failed: Connection closed
```

`Connection closed` — уже конкретика: TDLib дозвонился до `nebula` и получил
обрыв. Значит маршрут SNI до MTProxy есть, а Fake-TLS рукопожатие не проходит.
Первое, что нужно проверить: поднят ли контейнер `proxy-control-mtproxy` в
момент приёмки, отвечает ли `127.0.0.1:8445`, и совпадает ли секрет в
`secrets/users.conf` с тем, что проба передаёт в `addProxy`.

Проходят: `packages.host`, `nginx.routes`, `firewall.ufw`, все четыре
сертификата Let's Encrypt, `core.runtime` (панель поднимается и отвечает).

## 2. Как WARP устроен на рабочем сервере (снято с `ams-server`)

Это образец, который нужно воспроизвести автоматически.

**Клиент.** Официальный `cloudflare-warp` (в снятой версии `2026.7.1377.0`),
служба `warp-svc.service`, управление через `warp-cli --accept-tos`.
Режим — `WarpProxy on port 40000`, то есть локальный SOCKS5 на
`127.0.0.1:40000`. Никакого WireGuard-туннеля на хосте не поднимается: WARP
остаётся одной локальной точкой выхода, и это ровно та модель, которую
проект уже описывает.

**Расхождение с нашим кодом:** проект зашил порт `45000`
(`_WARP_PORT` в `installer/adapters/three_xui.py`), рабочий сервер использует
`40000`. Порт должен стать настраиваемым, со значением по умолчанию `40000`,
раз именно оно проверено в деле.

**Маршрутизация в Xray.** Outbound:

```json
{"tag": "WARP", "protocol": "socks",
 "settings": {"servers": [{"address": "127.0.0.1", "port": 40000, "users": []}]}}
```

Правила (`domainStrategy: AsIs`), в этом порядке:

1. `inboundTag: ["api"] → api`
2. `ip: ["geoip:private"] → blocked`
3. `protocol: ["bittorrent"] → blocked`
4. точечные блокировки по IP
5. `domain: [...] → WARP` — выборочный список, на снятом сервере это
   `geosite:openai`, `geosite:anthropic`, `domain:chat.openai.com`,
   `domain:claude.ai`, `geosite:tiktok`, `geosite:reddit`,
   `geosite:google-gemini`, `geosite:google-play`, `domain:2ip.ru`

Ключевое: **правило WARP идёт последним среди содержательных**, а всё
несовпавшее уходит через `direct`. Это и есть «выборочно отправлять трафик в
WARP».

## 3. Задачи

### 3.1 Добить установку

- разобрать `Connection closed` в приёмке MTProxy;
- прогонять установку **с полным журналом**: сохранять `install.err`,
  `docker compose logs`, `journalctl -u nginx`, состояние контейнеров на
  каждом заходе, а не только последнюю строку ошибки;
- довести до `status: active` и проверить снаружи: панели по HTTPS, инбаунды
  по открытым портам, MTProxy настоящим клиентом, Naive, Mieru.

### 3.2 Автоматический WARP

Установщик должен разворачивать WARP сам — владелец подтвердил, что
использовать сеть для установки компонентов нормально.

1. поставить `cloudflare-warp` из официального репозитория Cloudflare
   (ключ репозитория + apt source), версию зафиксировать в
   `release/external-artifacts.json` как остальные внешние артефакты;
2. `warp-cli --accept-tos registration new` при отсутствии регистрации;
3. `warp-cli --accept-tos mode proxy` и `warp-cli --accept-tos proxy port <порт>`;
4. `warp-cli --accept-tos connect`, дождаться `Status update: Connected`;
5. приёмка: SOCKS5 на `127.0.0.1:<порт>` действительно проксирует — запросить
   через него внешний адрес и убедиться, что он **отличается** от адреса
   сервера. Открытого порта здесь мало, как выяснилось с инбаундами 3x-ui.

Всё это — отдельное владеемое действие с откатом: разворачивал установщик —
он же и убирает.

### 3.3 Выборочная маршрутизация через 3x-ui

- добавить в конфигурацию список доменов WARP (сейчас `three_xui.warp_domains`
  существует, но недостижим — он принимается только в `managed-new`);
- при `warp = true` создавать outbound `WARP` (socks на локальный порт) и
  правило `domain: [...] → WARP` **после** блокирующих правил;
- по умолчанию предлагать в мастере проверенный на практике список
  (`geosite:openai`, `geosite:anthropic`, `geosite:tiktok`, `geosite:reddit`,
  `geosite:google-gemini`, `geosite:google-play`), с возможностью изменить;
- приёмка: запрос к домену из списка уходит через WARP (внешний адрес не
  совпадает с адресом сервера), запрос к домену вне списка — напрямую.

### 3.4 Подписка 3x-ui (девятый домен)

Отложена владельцем «на попозже», но домен уже выдан — `zenith`.
Состав работы описан в памяти проекта: поле домена в конфигурации и мастере,

## 4. Что уже исправлено этой серией

Тринадцать дефектов, найденных настоящей установкой и невидимых для стенда:
отсутствие `stream`-контекста в штатном `nginx.conf`; ручная выкладка пакетов
Mieru; выключенный UFW; невоспроизводимый отпечаток плана; подготовка действия
против ещё выключенного брандмауэра; блокировка повторной попытки после
завершённого отката; безымянная `Core command failed`; брандмауэр после
сертификатов; откат, оставлявший брандмауэр включённым; выброшенный вывод
команд; уже существующий владелец панели; образы, не пересобираемые из
релиза; проба, глотавшая свою же ошибку.

## 5. Правила работы, добытые дорогой ценой

- **Немая ошибка — первое, что нужно чинить.** Половина дефектов этой серии
  пряталась за сообщением, называвшим шаг, но не причину. Каждый раз, когда
  ошибка начинала говорить, следующий заход указывал на настоящую проблему.
- **Образ, собранный раньше, — это чужой код.** Compose переиспользует
  существующий образ; в идентичность образа должен входить отпечаток
  исходников, иначе исправление в релизе не доезжает.
- **Проверять открытый порт, а не запись в панели.** 3x-ui хранит инбаунд,
  который Xray не станет обслуживать, и показывает его включённым.
- **Запуская релиз в CI**, сверять `headSha` прогона с `git rev-parse
  origin/main`: однажды прогон шёл на предыдущем коммите, и часы ушли на
  разбор результатов кода, которого в прогоне не было.
