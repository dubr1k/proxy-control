# v4.0.0 — нативный Rust

[English](#english) · **Русский**

Предыдущий стабильный выпуск: [v3.3.0](https://github.com/dubr1k/proxy-control/releases/tag/v3.3.0).

## Русский

### Что изменилось

- **Нативный runtime.** Панель, менеджеры протоколов, MCP, установщик и агент версий работают на Rust. Установщик и агент поставляются готовыми статическими x86-64 Linux-бинарниками; собирать их на сервере не нужно. Python остаётся только во внешних инструментах разработки, сборки и приёмки, а не в runtime продукта.
- **Прежние рабочие интерфейсы.** Сохраняются API протоколов и Fleet v2, клиенты и доступы, подписки, одноразовые показы секретов, маршрутизация, цепи, полосы и мониторинг. Пути данных, имена контейнеров, числовые UID/GID и группы сокетов не переименовываются из-за смены языка.
- **Установщик изменился.** `install.sh`, `uninstall.sh` и хостовые скрипты вызывают проверенный нативный установщик. До выполнения кода из архива `install-release.sh` и `install-bootstrap` проверяют архив, манифест, типы файлов, права и дайджесты бинарников без Python. Формат `SHA256SUMS` из трёх файлов сохраняется; рядом по-прежнему публикуется собственная контрольная сумма `install-release.sh`.
- **Xray-core 26.10.21.** Обновлены pin архива и дайджесты трёх входящих файлов после отзыва upstream-версии 26.10.17. Вопросы мастера, новая установка и начальное состояние агента используют один pin.
- **Исправления восстановления.** Repair сохраняет выбранные оператором каталог версий и файл состояния; environment читается с правилами systemd, без shell expansion. Старые принадлежащие установщику Python-helper’ы переходят на нативный вызов с проверкой прежнего владения. Повторная установка роутера после отказа запуска использует сохранённые учётные данные, а не пытается заново инициализировать непустое состояние.
- **Исправления панели.** Ротация и удаление учётной записи MTProxy согласуют сохранённые ключи клиентских ссылок и подписок. Чрезмерно вложенный JSON отклоняется до валидации вместо остановки обработчика. Ошибки менеджеров сохраняют HTTP-статус и ответ своего протокола.

### Что меняется при переходе

1. **Только domain writer.** `PANEL_VNEXT_WRITER=legacy` больше не выбирает старый путь записи. Установка, которая использовала прежнее значение по умолчанию, после обновления работает через модель клиентов и доступов. Перед переходом сохраните согласованную копию базы и мастер-ключа; не создавайте новую базу вместо прежней.
2. **Fleet v1 удалён.** Старые mTLS ingress, node-agent, регистрация сертификатов и raw-command API не поставляются. Сначала перенесите каждый старый узел на Fleet v2. При обнаружении старых служб, overlay-файлов или контейнеров обновление отказывает до изменения файлов и базы; их тома и сертификаты не удаляются автоматически.
3. **Старые ручные инструменты удалены.** `scripts/proxyctl.py`, `scripts/mtproxy-deploy` и `scripts/check-deployment.sh` не являются точками входа этого выпуска. Используйте мастер или нативные команды по [справочнику установщика](../INSTALLER_REFERENCE.ru.md).
4. **Древние базы без migration runner не принимаются.** Если в непустой базе нет истории `schema_migrations`, сначала обновите её совместимым предыдущим выпуском. Нативная панель отказывает, не усыновляя и не переписывая такой файл. Базы с историей миграций проходят обычный путь обновления.
5. **Повреждённые и нестандартные данные проверяются строже.** Некорректные keyring/журналы, неподдерживаемые размеры чисел, невалидный UTF-8 и JSON со специальными нечисловыми значениями могут быть отклонены. Тексты некоторых ошибок и служебные HTTP-заголовки отличаются от Python-реализации. Поддерживаемые схемы, purpose ключей, формат секретов и канонические дайджесты Fleet v2 сохраняются. Unicode-нормализация использует более новые таблицы для недавно добавленных символов.

### Обновление с 3.3.0

**Не используйте кнопку обновления панели в интерфейсе 3.3.0.** Этот путь не переносит хостового агента: сборка нового образа должна отказать на неполном поколении исходников, а старый агент — восстановить прежнее. Поддерживаемый переход — только проверенный `install-release.sh --update`.

Сделайте [резервную копию](../BACKUP_RESTORE.ru.md). Обычным пользователем с `sudo`, в пустом рабочем каталоге, скачайте файлы именно выбранного выпуска:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v4.0.0/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v4.0.0/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh --update --version 4.0.0
```

Продолжайте только после успешной проверки контрольной суммы и после публикации выбранного выпуска. Во флоте обновляйте узлы раньше центра. Установщик сначала заменяет и проверяет точную версию Rust-агента, затем обновляет панель и менеджеры, согласует ingress, Compose и владение. Нераспознанный операторский `ExecStart` — причина остановки, а не разрешение перезаписать unit. Подробности и восстановление: [обновление и откат](../UPGRADING.ru.md).

При откате восстанавливайте **всё прежнее поколение**, включая базу, образы, секреты и конфигурацию. Не запускайте старую панель с произвольно оставленной новой базой и не удаляйте тома ради повторной попытки.

### Новая установка

Ubuntu 24.04 LTS x86-64, обычный пользователь с `sudo`, подготовленные DNS-имена. Скачайте и проверьте те же файлы, затем выполните `bash install-release.sh` без `--update`. Мастер и неинтерактивный путь описаны в [README](../../README.md#установка-человеком).

## English

### What changed

- **Native runtime.** The panel, protocol managers, MCP, installer and version-agent run in Rust. The installer and agent ship as static x86-64 Linux binaries; the host does not compile them. Python remains only in external development, build and acceptance tools, not the product runtime.
- **Existing operational interfaces.** Protocol and Fleet v2 APIs, clients and grants, subscriptions, one-time reveals, routing, chains, lanes and monitoring remain. Changing the implementation language does not rename data paths, containers, numeric UID/GID values or socket groups.
- **The installer changed.** `install.sh`, `uninstall.sh` and host scripts dispatch the verified native installer. Before executing archive code, `install-release.sh` and `install-bootstrap` check the archive, manifest, file types, modes and executable digests without Python. The three-file `SHA256SUMS` format remains; the installer script still has its separate checksum.
- **Xray-core 26.10.21.** The archive pin and three member digests replace the withdrawn upstream 26.10.17 release. Wizard prompts, fresh installation and seeded agent state use the same pin.
- **Recovery fixes.** Repair preserves operator-selected catalog and state paths; environment parsing follows systemd rules without shell expansion. Previously owned Python helpers migrate to native dispatch only after verifying their recorded ownership. Router reinstall after a failed start uses retained credentials instead of trying to initialize populated state again.
- **Panel fixes.** MTProxy account rotation and deletion reconcile credentials retained for client links and subscriptions. Excessively nested JSON is rejected before validation instead of stopping a worker. Manager errors retain their HTTP status and protocol-specific response.

### Transition boundaries

1. **Domain writer only.** `PANEL_VNEXT_WRITER=legacy` no longer selects the old writer. An installation using the former default moves to the clients-and-grants model. Keep a consistent database and master-key backup before updating; do not replace the existing database with a fresh one.
2. **Fleet v1 is removed.** Its mTLS ingress, node agent, certificate registration and raw-command APIs are not shipped. Move every old node to Fleet v2 first. An update detects old units, overlays or containers and refuses before changing release files or the database; it does not automatically remove their volumes or certificates.
3. **Old manual tools are removed.** `scripts/proxyctl.py`, `scripts/mtproxy-deploy` and `scripts/check-deployment.sh` are not entry points in this release. Use the wizard or native commands in the [installer reference](../INSTALLER_REFERENCE.en.md).
4. **Pre-migration-runner databases are refused.** A nonempty database without `schema_migrations` history needs a compatible previous release first. The native panel refuses without adopting or rewriting that file. Databases with migration history follow the normal upgrade path.
5. **Malformed and nonstandard data is checked more strictly.** Malformed keyrings/journals, unsupported integer sizes, invalid UTF-8 and JSON special nonnumeric values can be refused. Some error wording and transport headers differ from Python. Supported schemas, secret purposes and formats, and Fleet v2 canonical digests remain. Unicode normalization uses newer tables for recently assigned characters.

### Upgrading from 3.3.0

**Do not use the panel-update button in the 3.3.0 UI.** That path does not migrate the host agent: the new image build must refuse an incomplete source generation and the old agent restores the previous one. The supported transition is the verified `install-release.sh --update` path only.

Make a [backup](../BACKUP_RESTORE.en.md). As a regular user with `sudo`, in an empty working directory, download the chosen release's own files:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v4.0.0/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v4.0.0/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh --update --version 4.0.0
```

Continue only after checksum verification succeeds and the chosen release has been published. Update fleet nodes before the central panel. The installer replaces and verifies the exact Rust-agent release first, then updates the panel and managers and reconciles ingress, Compose and ownership. An unrecognized operator-custom `ExecStart` is a hard stop, not permission to overwrite the unit. Details and recovery: [upgrading and rollback](../UPGRADING.md).

Rollback restores **the complete previous generation**, including database, images, secrets and configuration. Do not run an old panel against an arbitrarily retained new database or delete volumes to force a retry.

### Fresh installation

Use Ubuntu 24.04 LTS x86-64, a regular user with `sudo`, and prepared DNS names. Download and verify the same files, then run `bash install-release.sh` without `--update`. Wizard and noninteractive instructions are in the [README](../../README.en.md#installation-by-a-human).
