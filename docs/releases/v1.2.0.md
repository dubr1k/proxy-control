# v1.2.0 — переименование клиентов и названий доступов

[English](#english) · **Русский**

Дата: 2026-10-17. Предыдущий выпуск: [v1.1.4](https://github.com/dubr1k/proxy-control/releases/tag/v1.1.4).

## Русский

### Что изменилось

- **Клиента можно переименовать.** На карточке клиента появилась кнопка «Переименовать». Новое имя видно в панели и на странице подписки; учётные записи на узлах и ссылка подписки не меняются.
- **У каждого доступа может быть своё название в подписке.** Окно доступа → «Название в подписке». Оно заменяет «узел · протокол» в sing-box/Throne, Clash, HTML и `raw`. Пустое название возвращает прежнее. Два доступа с одинаковым названием получают стабильный короткий суффикс, как и раньше.
- **Узлы переименовываются на экране «Узлы»** (включая локальный сервер), как и раньше: имя узла входит в название по умолчанию.
- **Приложение клиента увидит новые имена после обновления подписки.** Ссылка, логины и пароли остаются прежними; условные запросы подписки сразу получают новое содержимое.
- **Для ИИ-агентов** доступны инструменты MCP: переименование клиента, названия доступа и узла.

Миграция базы 22 добавляет колонку названия доступа; узлы получают её тем же обновлением. Протокол Fleet и публичный манифест v1 не меняются. Менеджеры протоколов и логика установщика не менялись. Скрипт установки в приложенных файлах привязан к версии 1.2.0 и контрольной сумме её архива.

### Установка на новый сервер

Требования: Ubuntu 24.04 LTS x86-64, собственные DNS-имена и обычный пользователь с `sudo`. Не запускайте мастер непосредственно от root. Подробно — [установка](https://github.com/dubr1k/proxy-control/blob/v1.2.0/README.md#установка-человеком) и [справочник](https://github.com/dubr1k/proxy-control/blob/v1.2.0/docs/INSTALLER_REFERENCE.ru.md).

В пустом рабочем каталоге скачайте файлы **именно v1.2.0**:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.2.0/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.2.0/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Продолжайте только после успешной проверки SHA-256. Мастер спросит домены и состав установки; на одном сервере с существующим Nginx/3x-ui выбирайте соответствующий режим сосуществования.

### Обновление существующей установки

Сначала сделайте [резервную копию](https://github.com/dubr1k/proxy-control/blob/v1.2.0/docs/BACKUP_RESTORE.ru.md). Скачайте и проверьте два файла командами выше, затем вместо запуска мастера выполните:

```bash
bash install-release.sh --update
```

В парке связанных панелей штатный порядок — узлы, затем центр. После обновления проверьте состояние служб и обновите подписку в клиентском приложении. Не удаляйте контейнерные тома, базу или секреты ради обновления.

### Ограничение проверки выпуска

Выпуск проверен автоматическими тестами затронутых областей, без нового полного установочного прогона. Диалоги переименования в браузере проверьте при первом использовании.

## English

### Changes

- **A client can be renamed.** The client card has a «Rename» button. The new name shows in the panel and on the subscription page; accounts on the nodes and the subscription link do not change.
- **Each access can carry its own name in the subscription.** Access window → «Name in the subscription». It replaces «node · protocol» in sing-box/Throne, Clash, HTML and `raw`. An empty name puts the default back. Two accesses with the same name get a stable short suffix, as before.
- **Nodes are renamed on the Nodes screen** (the local server included), as before: the node name is part of the default title.
- **The client's app shows the new names after it refreshes the subscription.** The link, usernames and passwords stay the same; conditional subscription requests receive the new content at once.
- **For AI agents** MCP tools are available to rename a client, an access title and a node.

Database migration 22 adds a column for the access name; nodes get it with the same update. The Fleet protocol and the public manifest v1 are unchanged. Protocol managers and installer logic are unchanged. The attached installation script is stamped with version 1.2.0 and its archive digest.

### Fresh installation

Use Ubuntu 24.04 LTS x86-64 and a regular user with `sudo`, not a root login. Prepare your DNS names and follow the [installation guide](https://github.com/dubr1k/proxy-control/blob/v1.2.0/README.en.md#installation-by-a-human) and [installer reference](https://github.com/dubr1k/proxy-control/blob/v1.2.0/docs/INSTALLER_REFERENCE.en.md).

In an empty working directory:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.2.0/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.2.0/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Continue only after checksum verification succeeds. The wizard asks for domains and components. Select the appropriate coexistence mode when Nginx/3x-ui is already installed.

### Upgrading

Make a [backup](https://github.com/dubr1k/proxy-control/blob/v1.2.0/docs/BACKUP_RESTORE.en.md), download and verify the same files, then run:

```bash
bash install-release.sh --update
```

The normal fleet update order is nodes first, central panel last. Check service health afterwards and refresh the existing subscription. Do not delete Docker volumes, the database or secrets as part of an update.

### Validation limitation

This release is checked by automated tests of the touched areas, without a new full installer acceptance run. Check the rename dialogs in the browser on first use.
