# v1.3.0 — AmneziaWG 1.5, 2.0 и 3.1

[English](#english) · **Русский**

Дата: 2026-10-17. Предыдущий выпуск: [v1.2.1](https://github.com/dubr1k/proxy-control/releases/tag/v1.2.1).

## Русский

### Что изменилось

- **Новый протокол — AmneziaWG** (необязательный): VPN поверх UDP, то есть WireGuard с маскировкой трафика. Доступны версии **1.5, 2.0 и 3.1**. Они несовместимы между собой, поэтому каждая работает на своём порту узла (по умолчанию 51820, 51821, 51822), а версию выбирают **для каждого клиента**: в окне «Узлы и доступы» у каждой версии своя колонка, и у человека может быть сразу несколько.
- **Конфиг выдаётся файлом и QR.** В окне доступа — «Показать конфиг», «Скачать .conf»; в подписки AmneziaWG не входит. Закрытый ключ клиента хранится только в панели, на узле лежит открытый; ротация выпускает новую пару ключей.
- **Включение.** Мастер установки спрашивает про AmneziaWG; в TOML — раздел `[amneziawg]` (`enabled`, `versions`, `host`, порты, `mtu`, `dns`). Установщик включает пересылку IPv4, открывает UDP-порты и разрешает пересылку для туннелей в брандмауэре, которым управляет. **Новый домен не нужен:** подойдёт любое имя, доходящее до сервера напрямую по UDP (не за проксирующим CDN), в том числе имя самой панели.
- На обзоре появилась карточка AmneziaWG с числом доступов по версиям и трафиком; инструменты MCP и навык для ИИ принимают версию.
- **Исправлено:** обновление NaiveProxy (Caddy) из панели снова проходит — версионному агенту не хватало записи в `/var/log/caddy`.

Миграция базы 23 расширяет список протоколов; узлы получают её тем же обновлением. Узел старее 1.3 AmneziaWG не получает: панель откажет сразу, а не оставит запрос ждать. Менеджеры остальных протоколов не менялись. При обновлении установщик собирает контейнер `awg-manager` только там, где AmneziaWG включён; его перезапуск ненадолго обрывает туннели, клиенты переподключаются сами.

### Установка на новый сервер

Требования: Ubuntu 24.04 LTS x86-64, собственные DNS-имена и обычный пользователь с `sudo`. Не запускайте мастер непосредственно от root. Подробно — [установка](https://github.com/dubr1k/proxy-control/blob/v1.3.0/README.md#установка-человеком) и [справочник](https://github.com/dubr1k/proxy-control/blob/v1.3.0/docs/INSTALLER_REFERENCE.ru.md).

В пустом рабочем каталоге скачайте файлы **именно v1.3.0**:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.3.0/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.3.0/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Продолжайте только после успешной проверки SHA-256. Мастер спросит домены и состав установки; на одном сервере с существующим Nginx/3x-ui выбирайте соответствующий режим сосуществования.

### Обновление существующей установки

Сначала сделайте [резервную копию](https://github.com/dubr1k/proxy-control/blob/v1.3.0/docs/BACKUP_RESTORE.ru.md). Скачайте и проверьте два файла командами выше, затем вместо запуска мастера выполните:

```bash
bash install-release.sh --update
```

В парке связанных панелей штатный порядок — узлы, затем центр. После обновления проверьте состояние служб и обновите подписку в клиентском приложении. Не удаляйте контейнерные тома, базу или секреты ради обновления.

### Ограничение проверки выпуска

Выпуск проверен автоматическими тестами затронутых областей, без нового полного установочного прогона. Сквозную проверку AmneziaWG (панель → менеджер → клиент для версий 1.5, 2.0, 3.1) выполните на своём сервере и в своей сети: работа обхода зависит от провайдера.

## English

### Changes

- **A new protocol — AmneziaWG** (optional): a VPN over UDP, i.e. WireGuard with traffic obfuscation. Versions **1.5, 2.0 and 3.1** are available. They are not compatible with one another, so each runs on its own port of the node (51820, 51821, 51822 by default), and the version is chosen **per client**: in the «Nodes and accesses» window every version has its own column, and one person can hold several at once.
- **The config is given as a file and a QR.** The access window has «Show config» and «Download .conf»; AmneziaWG is not part of subscriptions. The client's private key is kept only in the panel and the node holds the public one; rotation issues a new key pair.
- **Enabling it.** The installer wizard asks about AmneziaWG; in TOML there is an `[amneziawg]` section (`enabled`, `versions`, `host`, ports, `mtu`, `dns`). The installer turns on IPv4 forwarding, opens the UDP ports and allows forwarding for the tunnels in the firewall it manages. **No new domain is needed:** any name that reaches the server directly over UDP (not behind a proxying CDN) works, including the panel's own name.
- The overview has an AmneziaWG card with the number of accesses per version and the traffic; the MCP tools and the AI skill take the version.
- **Fixed:** updating NaiveProxy (Caddy) from the panel works again — the version agent lacked write access to `/var/log/caddy`.

Database migration 23 widens the protocol list; nodes get it with the same update. A node older than 1.3 does not get AmneziaWG: the panel refuses at once instead of leaving the request waiting. The other protocols' managers are unchanged. On update the installer builds the `awg-manager` container only where AmneziaWG is enabled; restarting it briefly drops the tunnels and clients reconnect on their own.

### Fresh installation

Use Ubuntu 24.04 LTS x86-64 and a regular user with `sudo`, not a root login. Prepare your DNS names and follow the [installation guide](https://github.com/dubr1k/proxy-control/blob/v1.3.0/README.en.md#installation-by-a-human) and [installer reference](https://github.com/dubr1k/proxy-control/blob/v1.3.0/docs/INSTALLER_REFERENCE.en.md).

In an empty working directory:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.3.0/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.3.0/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Continue only after checksum verification succeeds. The wizard asks for domains and components. Select the appropriate coexistence mode when Nginx/3x-ui is already installed.

### Upgrading

Make a [backup](https://github.com/dubr1k/proxy-control/blob/v1.3.0/docs/BACKUP_RESTORE.en.md), download and verify the same files, then run:

```bash
bash install-release.sh --update
```

The normal fleet update order is nodes first, central panel last. Check service health afterwards and refresh the existing subscription. Do not delete Docker volumes, the database or secrets as part of an update.

### Validation limitation

This release is checked by automated tests of the touched areas, without a new full installer acceptance run. Run an end-to-end check of AmneziaWG (panel → manager → client for 1.5, 2.0, 3.1) on your own server and network: how well the obfuscation works depends on the provider.
