# Proxy Control v0.2.0-beta.1

> **Статус / Status:** Beta. Локальный control plane v0.2 — клиенты, доступы, зашифрованное хранилище учётных данных и подписки на отдельном домене. Гейт — только стенд `ams-test`; CI подтверждает байты и публикует. / Beta. The v0.2 local control plane — clients, accesses, an encrypted credential store and client subscriptions on a dedicated domain. The gate is the lab host only; CI confirms the bytes and publishes.

## Русский

### Что нового

- **Клиенты и доступы.** Панель владеет учётными записями всех трёх протоколов: импорт существующих (только чтение менеджеров), «Принять доступ» (MTProxy и Naive — чтением, Mieru — только с явной ротацией), выдача новых доступов одной журналируемой операцией с честным исходом `succeeded | compensated | manual_intervention_required`.
- **Зашифрованное хранилище.** Учётные данные лежат в базе под мастер-ключом (AES-256-GCM), который установщик создаёт и сохраняет сам; без ключа при наличии секретов панель не стартует. Резервная копия ключа хранится отдельно от базы — см. `docs/BACKUP_RESTORE.ru.md`.
- **Подписка клиента.** Одна ссылка `https://<домен подписки>/s/<token>` на все доступы клиента: `raw` (текст, без base64), `singbox` (Karing; `&client=singbox` — только naive для официального sing-box), `clash` (mihomo, TCP и UDP), `manifest`, `html`. Токен хранится хэшем, показывается один раз, не логируется нигде на пути; `ETag` меняется, когда меняется набор доступов; матрица совместимости честно называет, что клиент не умеет.
- **Отдельный домен подписки** — `subscription` в `[domains]` `install.toml` (мастер спрашивает его): SAN в сертификате, свой `server` в Nginx с `access_log off`, на домене панели путь `/s/` не существует.
- **Миграции и аудит.** Единая граница БД, версионные миграции (`db-migrate`, `db-status`), апгрейд базы v0.1.0 на месте; аудит пишется в транзакции изменения, `X-Request-Id` связывает ответ и строку журнала.
- **Флаг писателя** `PANEL_VNEXT_WRITER=legacy|domain`: старые API неотличимы снаружи, порядок перехода описан в `PANEL.ru.md`.

### Исправлено в установщике

- Профиль `full`: панель после установки не знала NaiveProxy (адаптеры Naive и Mieru поднимали Compose только со своим overlay).
- `repair` на хосте с `managed-new` 3x-ui падал на проверке маршрутов и на гонке рестарта панели 3x-ui.
- Завершённый `uninstall` блокировал следующий `install` («an installer transaction already exists»); теперь `uninstall` → `install` перерисовывает владеемые файлы новым релизом поверх сохранённых данных (`managed-new` 3x-ui по-прежнему требует `--purge-data` или переноса `/etc/x-ui/x-ui.db`).

### Установка

Скачайте `proxy-control-v0.2.0-beta.1.tar.gz`, `SHA256SUMS`, `release-manifest.json`, `sbom.spdx.json`. `install-bootstrap` отказывает предрелизным версиям — для беты распакуйте архив после проверки `sha256sum --check SHA256SUMS` и запустите `python3 -m installer.cli wizard` из каталога `proxy-control/`. Полный профиль с `managed-new` и подпиской клиентов требует **9 доменов** (восемь из v0.1.0 плюс домен подписки клиентов) — именно этот набор проверен на стенде; необязательная подписка 3x-ui (`three_xui.subscription_domain`, функция v0.1.0) добавляет десятый и в этом выпуске живьём не проверялась; без подписок — 8.

Апгрейд с v0.1.0: мастер-ключ создаст установщик; данные, тома и учётные данные сохраняются. После апгрейда — импорт существующих пользователей → «Принять доступ» → `PANEL_VNEXT_WRITER=domain` (`docs/UPGRADING.md`).

### Проверено для этого выпуска (на стенде)

- `REMOTE_GATE_FULL_OK` (1551+ тестов), `REMOTE_GATE_COMPOSE_OK`, `REMOTE_GATE_LAB_CONTAINER_OK`, `REMOTE_GATE_LAB_HOST_OK` (18 сценариев: install → repair → idempotence → reboot/crash recovery → uninstall → coexistence);
- апгрейд-drill на реальных данных v0.1.0: миграции 1–8, fail-closed без ключа;
- живая установка профилем `full` с `managed-new` 3x-ui и доменом подписки, сертификаты Let's Encrypt;
- живая подписка: 200/ETag/304/404, ротация и отзыв, события; **официальный sing-box 1.14.0** гонит трафик через naive, **mihomo 1.19.30** — через mieru по TCP и UDP; canary-скан логов и дампа БД без ключа — токенов и паролей нет;
- backup/restore drill: подписка рендерится из восстановленной пары БД + ключ, чужой ключ отвергается;
- переустановка `uninstall` → `install` итоговым архивом поверх сохранённых данных: сертификаты не перевыпускались, мастер-ключ и база панели подхвачены, приёмка подписки пройдена заново.

Не заявляются как завершённые: Fleet v2, routing, Xray-router (roadmap `docs/VNEXT_ARCHITECTURE.md`); импорт подписки в Karing на устройстве — ручная проверка владельца.

## English

### What is new

- **Clients and accesses.** The panel owns the accounts of all three protocols: read-only import of existing ones, "Adopt" (MTProxy and Naive by capture, Mieru only with an explicit rotation), new accesses through one journaled operation with an honest outcome `succeeded | compensated | manual_intervention_required`.
- **Encrypted store.** Credentials live in the database under a master key (AES-256-GCM) the installer creates and preserves; with encrypted rows and no key the panel refuses to start. Back the key up separately from the database — `docs/BACKUP_RESTORE.en.md`.
- **Client subscription.** One URL `https://<subscription domain>/s/<token>` for every access of a client: `raw` (plain text, no base64), `singbox` (Karing; `&client=singbox` is naive-only for the official core), `clash` (mihomo, TCP and UDP), `manifest`, `html`. The token is stored as a hash, revealed once, logged nowhere on the path; the `ETag` moves when the set of accesses moves; the compatibility matrix names what a client cannot consume.
- **A dedicated subscription domain** — `subscription` under `[domains]` in `install.toml` (the wizard asks for it): a SAN on the certificate, its own Nginx `server` with `access_log off`; on the panel's domain `/s/` does not exist.
- **Migrations and audit.** One database boundary, versioned migrations (`db-migrate`, `db-status`), in-place upgrade of a v0.1.0 database; audit rows written inside the change's transaction, `X-Request-Id` ties a response to its row.
- **Writer flag** `PANEL_VNEXT_WRITER=legacy|domain`: the old APIs are indistinguishable from outside; the cut-over order is in `PANEL.en.md`.

### Installer fixes

- `full` profile: the panel came up without NaiveProxy (the Naive and Mieru adapters each started Compose with only their own overlay).
- `repair` on a `managed-new` 3x-ui host failed on the route check and on the panel restart race.
- A finished `uninstall` blocked the next `install` ("an installer transaction already exists"); `uninstall` → `install` now re-renders owned files from a new release over the preserved data (`managed-new` 3x-ui still needs `--purge-data` or `/etc/x-ui/x-ui.db` moved away).

### Installing

Download `proxy-control-v0.2.0-beta.1.tar.gz`, `SHA256SUMS`, `release-manifest.json`, `sbom.spdx.json`. `install-bootstrap` refuses pre-release versions — for the beta, verify with `sha256sum --check SHA256SUMS`, extract, and run `python3 -m installer.cli wizard` from `proxy-control/`. The full profile with `managed-new` and client subscriptions needs **9 domains** (the eight of v0.1.0 plus the client subscription domain) — this is the set verified on the lab host; the optional 3x-ui subscription (`three_xui.subscription_domain`, a v0.1.0 feature) adds a tenth and was not exercised live for this release; without subscriptions — 8.

Upgrading from v0.1.0: the installer creates the master key; data, volumes and credentials are preserved. Afterwards: import existing users → "Adopt" → `PANEL_VNEXT_WRITER=domain` (`docs/UPGRADING.md`).

### Verified for this release (on the lab host)

- `REMOTE_GATE_FULL_OK` (1551+ tests), `REMOTE_GATE_COMPOSE_OK`, `REMOTE_GATE_LAB_CONTAINER_OK`, `REMOTE_GATE_LAB_HOST_OK` (18 scenarios: install → repair → idempotence → reboot/crash recovery → uninstall → coexistence);
- upgrade drill on real v0.1.0 data: migrations 1–8, fail-closed without the key;
- a live `full` install with `managed-new` 3x-ui and the subscription domain, Let's Encrypt certificates;
- the live subscription: 200/ETag/304/404, rotation and revocation, events; **official sing-box 1.14.0** carries traffic through naive, **mihomo 1.19.30** through mieru over TCP and UDP; a canary scan of logs and of the key-less database dump finds no token and no password;
- backup/restore drill: the subscription renders from the restored database + key pair, a foreign key is refused;
- `uninstall` → `install` of the final archive over the preserved data: no certificate re-issuance, the master key and the panel database picked up, the subscription acceptance passed again.

Not claimed as finished: Fleet v2, routing, the Xray router (roadmap in `docs/VNEXT_ARCHITECTURE.md`); importing the subscription into Karing on a device is the owner's manual check.

Контрольная сумма архива / archive checksum: записывается владельцем при тегировании из `dist/SHA256SUMS` на стенде (`lab-sha256:` в аннотации тега) / recorded by the owner at tag time from `dist/SHA256SUMS` on the lab host (`lab-sha256:` in the tag annotation).
