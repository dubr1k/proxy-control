# v1.1.3 — различимые имена подключений в подписках

[English](#english) · **Русский**

Дата: 2026-10-11. Предыдущий выпуск: [v1.1.2](https://github.com/dubr1k/proxy-control/releases/tag/v1.1.2).

## Русский

### Что изменилось

- **Конфиги с разных узлов больше не называются одинаково.** Подписка использует имя узла и протокол: `Amsterdam · Naive`, `Frankfurt · Mieru · TCP 8443`. Одинаковый логин на нескольких серверах не мешает различать подключения.
- **Совпадающие имена получают стабильный короткий суффикс доступа.** Перестановка записей и отключение соседнего доступа не меняют имя оставшегося. Визуально одинаковые Unicode-имена нормализуются перед поиском совпадений.
- **Общие правила для клиентов.** Имена обновлены в sing-box JSON (Karing/Throne), Clash/mihomo, HTML и подписях Naive/Mieru в raw. У Mieru в JSON/YAML сохраняются транспорт и порт; ссылка Telegram MTProxy остаётся без изменений.
- **Переименование узла корректно обновляет подписку.** ETag учитывает отображаемые имена, включая отключённые доступы на HTML-странице.

Логины, пароли, адреса серверов и ссылки подписок не меняются. Миграций базы и изменений протокола Fleet нет; формат публичного manifest v1 сохранён. Менеджеры протоколов и логика установщика не менялись. Скрипт установки в приложенных файлах привязан к версии 1.1.3 и контрольной сумме её архива.

### Как получить новые имена в Throne

1. Обновите панель, выдающую подписку.
2. При необходимости задайте понятные имена на экране «Узлы», включая локальный сервер.
3. В Throne обновите **существующую** подписку формата `singbox` (вариант Karing). Создавать клиента заново или менять ссылку не нужно.
4. Проверьте выбранное подключение: сохранение выбора после переименования зависит от приложения.

### Установка на новый сервер

Требования: Ubuntu 24.04 LTS x86-64, собственные DNS-имена и обычный пользователь с `sudo`. Не запускайте мастер непосредственно от root. Подробно — [установка](https://github.com/dubr1k/proxy-control/blob/v1.1.3/README.md#установка-человеком) и [справочник](https://github.com/dubr1k/proxy-control/blob/v1.1.3/docs/INSTALLER_REFERENCE.ru.md).

В пустом рабочем каталоге скачайте файлы **именно v1.1.3**:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.1.3/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.1.3/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Продолжайте только после успешной проверки SHA-256. Мастер спросит домены и состав установки; на одном сервере с существующим Nginx/3x-ui выбирайте соответствующий режим сосуществования.

### Обновление существующей установки

Сначала сделайте [резервную копию](https://github.com/dubr1k/proxy-control/blob/v1.1.3/docs/BACKUP_RESTORE.ru.md). Скачайте и проверьте два файла командами выше, затем вместо запуска мастера выполните:

```bash
bash install-release.sh --update
```

В парке связанных панелей штатный порядок — узлы, затем центр. После обновления проверьте состояние служб и обновите подписку в клиентском приложении. Не удаляйте контейнерные тома, базу или секреты ради обновления.

## English

### Changes

- **Connections from different nodes have distinct names.** Subscriptions use the node name and protocol, for example `Amsterdam · Naive` and `Frankfurt · Mieru · TCP 8443`, even when accounts share the same username.
- **Duplicate names receive stable short grant suffixes.** Reordering entries or disabling a sibling does not rename the remaining profile. Canonically equivalent Unicode names are normalized before collision detection.
- **Shared naming across formats.** sing-box JSON (Karing/Throne), Clash/mihomo, HTML and Naive/Mieru raw labels follow the same rules. Mieru JSON/YAML names retain transport and port. Telegram MTProxy links are unchanged.
- **Node renames invalidate subscription caches**, including disabled accesses displayed on the HTML page.

Usernames, passwords, server addresses and subscription URLs are unchanged. There are no database migrations or Fleet protocol changes; the public manifest v1 contract is preserved. Protocol managers and installer logic are unchanged. The attached installation script is stamped with version 1.1.3 and its archive digest.

### Refreshing Throne

Update the panel serving the subscription, optionally rename nodes on the Nodes screen, then refresh the existing `singbox` subscription (Karing variant) in Throne. No new client or URL is required. Check the selected connection afterwards: selection retention across a rename depends on the app.

### Fresh installation

Use Ubuntu 24.04 LTS x86-64 and a regular user with `sudo`, not a root login. Prepare your DNS names and follow the [installation guide](https://github.com/dubr1k/proxy-control/blob/v1.1.3/README.en.md#installation-by-a-human) and [installer reference](https://github.com/dubr1k/proxy-control/blob/v1.1.3/docs/INSTALLER_REFERENCE.en.md).

In an empty working directory:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.1.3/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.1.3/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Continue only after checksum verification succeeds. The wizard asks for domains and components. Select the appropriate coexistence mode when Nginx/3x-ui is already installed.

### Upgrading

Make a [backup](https://github.com/dubr1k/proxy-control/blob/v1.1.3/docs/BACKUP_RESTORE.en.md), download and verify the same files, then run:

```bash
bash install-release.sh --update
```

The normal fleet update order is nodes first, central panel last. Check service health afterwards and refresh the existing subscription. Do not delete Docker volumes, the database or secrets as part of an update.
