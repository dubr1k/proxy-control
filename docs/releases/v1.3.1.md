# v1.3.1 — Telemt из выпусков апстрима

[English](#english) · **Русский**

Дата: 2026-10-17. Предыдущий выпуск: [v1.3.0](https://github.com/dubr1k/proxy-control/releases/tag/v1.3.0).

## Русский

### Что изменилось

- **Telemt (MTProto) обновляется из панели до последнего выпуска апстрима.** Образ `mtproxymax-telemt` отстаёт от `telemt/telemt` (3.5.9 против 3.5.14), поэтому экран «Версии» теперь предлагает и выпуски апстрима: агент версий скачивает бинарь, сверяет SHA-256 из метаданных выпуска, собирает на хосте образ поверх закреплённого базового образа и переключает `mtproxy` на него. При сбое прежнее состояние возвращается и проверяется. Обновление ненадолго обрывает сессии MTProxy.
- Остальное без изменений: миграций базы нет, протокол Fleet и установщик не менялись.

### Установка на новый сервер

Требования: Ubuntu 24.04 LTS x86-64, собственные DNS-имена и обычный пользователь с `sudo`. Не запускайте мастер непосредственно от root. Подробно — [установка](https://github.com/dubr1k/proxy-control/blob/v1.3.1/README.md#установка-человеком) и [справочник](https://github.com/dubr1k/proxy-control/blob/v1.3.1/docs/INSTALLER_REFERENCE.ru.md).

В пустом рабочем каталоге скачайте файлы **именно v1.3.1**:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.3.1/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.3.1/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Продолжайте только после успешной проверки SHA-256. Мастер спросит домены и состав установки; на одном сервере с существующим Nginx/3x-ui выбирайте соответствующий режим сосуществования.

### Обновление существующей установки

Сначала сделайте [резервную копию](https://github.com/dubr1k/proxy-control/blob/v1.3.1/docs/BACKUP_RESTORE.ru.md). Скачайте и проверьте два файла командами выше, затем вместо запуска мастера выполните:

```bash
bash install-release.sh --update
```

В парке связанных панелей штатный порядок — узлы, затем центр. После обновления проверьте состояние служб и обновите подписку в клиентском приложении. Не удаляйте контейнерные тома, базу или секреты ради обновления.

### Ограничение проверки выпуска

Выпуск проверен автоматическими тестами затронутых областей, без нового полного установочного прогона. Версию Telemt проверьте на своём узле после обновления.

## English

### Changes

- **Telemt (MTProto) can be updated from the panel to the latest upstream release.** The `mtproxymax-telemt` image lags behind `telemt/telemt` (3.5.9 against 3.5.14), so the Versions screen now also offers upstream releases: the version agent downloads the binary, checks the SHA-256 from the release metadata, builds an image on the host on top of the pinned base image and switches `mtproxy` to it. On a failure the previous state is restored and verified. The update briefly drops MTProxy sessions.
- Everything else is unchanged: no database migrations, and the Fleet protocol and the installer did not change.

### Fresh installation

Use Ubuntu 24.04 LTS x86-64 and a regular user with `sudo`, not a root login. Prepare your DNS names and follow the [installation guide](https://github.com/dubr1k/proxy-control/blob/v1.3.1/README.en.md#installation-by-a-human) and [installer reference](https://github.com/dubr1k/proxy-control/blob/v1.3.1/docs/INSTALLER_REFERENCE.en.md).

In an empty working directory:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.3.1/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.3.1/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Continue only after checksum verification succeeds. The wizard asks for domains and components. Select the appropriate coexistence mode when Nginx/3x-ui is already installed.

### Upgrading

Make a [backup](https://github.com/dubr1k/proxy-control/blob/v1.3.1/docs/BACKUP_RESTORE.en.md), download and verify the same files, then run:

```bash
bash install-release.sh --update
```

The normal fleet update order is nodes first, central panel last. Check service health afterwards and refresh the existing subscription. Do not delete Docker volumes, the database or secrets as part of an update.

### Validation limitation

This release is checked by automated tests of the touched areas, without a new full installer acceptance run. Check the Telemt version on your node after updating.
