# v1.2.1 — переименование клиентов и названий доступов

[English](#english) · **Русский**

Дата: 2026-10-17. Предыдущий выпуск: [v1.2.0](https://github.com/dubr1k/proxy-control/releases/tag/v1.2.0).

## Русский

### Что изменилось

- **Обновлены компоненты.** Xray — до 26.10.17 (последняя бета), Mieru/mita — до 3.38.1, Caddy — до 2.11.7 (сборка для Naive и пограничный Caddy), 3x-ui для режима `managed-new` — до 3.10.2, образ MTProto (Telemt) — до 3.5.9.
- **Xray-router обновляется до последней беты из панели** (экран «Версии»): проверка обновлений учитывает пре-релизы Xray.
- Установщик и скрипт `install-release.sh` используют те же закрепления: свежая установка ставит то же, что получает узел обновлением.

Миграций базы нет, протокол Fleet не меняется.

### Установка на новый сервер

Требования: Ubuntu 24.04 LTS x86-64, собственные DNS-имена и обычный пользователь с `sudo`. Не запускайте мастер непосредственно от root. Подробно — [установка](https://github.com/dubr1k/proxy-control/blob/v1.2.1/README.md#установка-человеком) и [справочник](https://github.com/dubr1k/proxy-control/blob/v1.2.1/docs/INSTALLER_REFERENCE.ru.md).

В пустом рабочем каталоге скачайте файлы **именно v1.2.1**:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.2.1/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.2.1/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Продолжайте только после успешной проверки SHA-256. Мастер спросит домены и состав установки; на одном сервере с существующим Nginx/3x-ui выбирайте соответствующий режим сосуществования.

### Обновление существующей установки

Сначала сделайте [резервную копию](https://github.com/dubr1k/proxy-control/blob/v1.2.1/docs/BACKUP_RESTORE.ru.md). Скачайте и проверьте два файла командами выше, затем вместо запуска мастера выполните:

```bash
bash install-release.sh --update
```

В парке связанных панелей штатный порядок — узлы, затем центр. После обновления проверьте состояние служб и обновите подписку в клиентском приложении. Не удаляйте контейнерные тома, базу или секреты ради обновления.

### Ограничение проверки выпуска

Выпуск проверен автоматическими тестами затронутых областей, без нового полного установочного прогона. Новые версии компонентов проверьте на своём узле после обновления.

## English

### Changes

- **Components are updated.** Xray to 26.10.17 (the latest beta), Mieru/mita to 3.38.1, Caddy to 2.11.7 (the Naive build and the edge Caddy), 3x-ui for `managed-new` to 3.10.2, the MTProto (Telemt) image to 3.5.9.
- **The Xray-router can be updated to the latest beta from the panel** (the Versions screen): the update check takes Xray pre-releases into account.
- The installer and `install-release.sh` use the same pins: a fresh installation sets up what a node gets by updating.

There are no database migrations and the Fleet protocol is unchanged.

### Fresh installation

Use Ubuntu 24.04 LTS x86-64 and a regular user with `sudo`, not a root login. Prepare your DNS names and follow the [installation guide](https://github.com/dubr1k/proxy-control/blob/v1.2.1/README.en.md#installation-by-a-human) and [installer reference](https://github.com/dubr1k/proxy-control/blob/v1.2.1/docs/INSTALLER_REFERENCE.en.md).

In an empty working directory:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.2.1/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.2.1/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Continue only after checksum verification succeeds. The wizard asks for domains and components. Select the appropriate coexistence mode when Nginx/3x-ui is already installed.

### Upgrading

Make a [backup](https://github.com/dubr1k/proxy-control/blob/v1.2.1/docs/BACKUP_RESTORE.en.md), download and verify the same files, then run:

```bash
bash install-release.sh --update
```

The normal fleet update order is nodes first, central panel last. Check service health afterwards and refresh the existing subscription. Do not delete Docker volumes, the database or secrets as part of an update.

### Validation limitation

This release is checked by automated tests of the touched areas, without a new full installer acceptance run. Check the new component versions on your node after updating.
