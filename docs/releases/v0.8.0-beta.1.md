## Русский

### Что это за выпуск

Поручение владельца: *«посмотри, как устроен UI маршрутизации в 3x-ui и как добавляются
аутбаунды — у нас это всё может работать через Xray; адаптируй под наш дизайн и интегрируй;
geodata — возьми от Loyalsoldier и поставь автообновление, дай добавлять сторонние списки по
ссылке; пресеты — да; WireGuard не нужен; почему пользователи узлов не появляются в центре сами,
как в 3x-ui — сделай»*. Ответ выпуска:

- **Свои выходы** — VPN или прокси как аутбаунд роутера узла: форма по протоколу или импорт
  ссылки, проверка «что видит дальний конец» (IP, colo, задержка), выбор в «Куда» у правила и у
  «по умолчанию»; секрет в escrow и только в intent своего узла.
- **Таблица правил и быстрые настройки** — «что / куда / заметка», модалка правила с
  подсказчиком кодов geodata и селектором протокола сниффера; переключатели «Торренты → блок»,
  «Реклама → блок», «RU → напрямую» как обычные правила с меткой.
- **Geodata** — списки роутера живут в его состоянии, сеются из пина, обновляются из
  Loyalsoldier или своих URL транзакцией с проверкой, автообновление по интервалу; панель
  показывает версию и число кодов.
- **Автоимпорт** — связанная панель отдаёт своих пользователей центру на каждом heartbeat:
  одно имя — один клиент во всех протоколах и на всех узлах; **одношаговый клиент** — имя, узел,
  протоколы; поле «Узел» в диалогах MTProxy/Naive/Mieru; подписки на центре.
- Мелочи UI: бренд-терминал в боковой панели, явное закрытие диалогов, отступ плашек.

Как это устроено — [ROUTING](../ROUTING.ru.md) «Свои выходы, быстрые настройки и geodata»,
[XRAY_ROUTER](../XRAY_ROUTER.ru.md) «Geodata и свои выходы», [FLEET](../../FLEET.ru.md) «Импорт
существующих пользователей»; что именно добавилось — [CHANGELOG.ru.md](../../CHANGELOG.ru.md);

### Что нашла проверка

- **Повторный импорт учётки, которую автоимпорт уже принял, отвечал 422** «already managed by a central panel» — нашёл tier `lab-host` (сценарий `fleet`): узел к тому моменту считал учётку центральной, а проверка владения шла раньше проверки «уже привязана». Порядок исправлен: своя связь — идемпотентный `already_linked`, отказ — только для учёток чужого центра; тест.
- **Добавление, проверка, включение или удаление выхода и действия с geodata перезагружали экран «Маршрутизация» и выбрасывали несохранённые правила** — нашёл tier `ui` (правила, добавленные до выхода, пропадали из сохранённой политики). Теперь обновляются только цели (свои выходы) и блок geodata, карточка перерисовывается, черновик остаётся.
- **Версия выпуска Loyalsoldier терялась** (`version: null` после удачного обновления) — нашла живая проверка ams-server → AMS_Z: GitHub называет релиз только на первом хопе редиректа `releases/latest/download/…`, последний хоп — подписанный URL asset'а без тега. Версия берётся с хопа, который её называет; все хопы — только https; тест.
- Лабораторные сценарии переписаны под v0.8: `fleet` ждёт, пока связь сама подхватит пользователей узла (`auto_import`, `node.import` в журнале аудита), и проверяет идемпотентность ручного импорта; `ui` ждёт загрузки политики после пробы выхода и чистит правило/выход через API, а не кликом по таблице.

## English

### What this release is

The owner's brief: *«look at how 3x-ui does routing and outbounds — all of that can run through
Xray here; adapt it to our design; geodata from Loyalsoldier with automatic updates, plus
third-party lists by URL; presets — yes; no WireGuard; why don't node users appear on the
central by themselves, as in 3x-ui — make it so»*. The release answers with:

- **Custom exits** — a VPN or a proxy as an outbound of the node's router: a form per protocol
  or a share-link import, a test of what the far end sees (IP, colo, latency), a choice in a
  rule's «Куда» and in the default; the credential escrowed and only in its node's intent.
- **A rule table and quick settings** — «what / where / note», a rule modal with geodata code
  suggestions and the sniffed-protocol selector; the toggles «Торренты → блок», «Реклама →
  блок», «RU → напрямую» as ordinary marked rules.
- **Geodata** — the router's lists live in its state, seeded from the pin, refreshed from
  Loyalsoldier or your URLs as a verified transaction, automatically at an interval; the panel
  shows the version and the code counts.
- **Auto-import** — a linked panel hands its users to the central on every heartbeat: one name
  is one client across protocols and nodes; **one-step clients** — name, node, protocols; a
  «Узел» field in the MTProxy/Naive/Mieru dialogs; subscriptions on the central.
- UI details: the terminal brand in the sidebar, explicit dialog closing, note margins.

Design — [ROUTING](../ROUTING.en.md) «Custom exits, quick settings and geodata», [XRAY_ROUTER](../XRAY_ROUTER.en.md)
«Geodata and custom exits», [FLEET](../../FLEET.en.md) «Import existing users»; changes —
[CHANGELOG.md](../../CHANGELOG.md); upgrade order — [UPGRADING](../UPGRADING.md) «Upgrading to v0.8».

### What the verification found

- **A repeated import of an account auto-import had already adopted answered 422** «already managed by a central panel» — found by the `lab-host` tier (`fleet` scenario): by then the node reported the account as central-owned, and the ownership check ran before the «already linked» one. Order fixed: this central's own link is an idempotent `already_linked`, the refusal is for another central's accounts only; test.
- **Adding, testing, enabling or deleting an exit and the geodata actions reloaded the Routing screen and threw the unsaved rules away** — found by the `ui` tier (rules added before the exit were missing from the saved policy). Now only the targets (custom exits) and the geodata block are refetched and the card is redrawn; the draft stays.
- **The Loyalsoldier release version was lost** (`version: null` after a successful update) — found by the live check ams-server → AMS_Z: GitHub names the release only on the first hop of `releases/latest/download/…`, the last hop is a signed asset URL without the tag. The version now comes from the hop that names it; every hop must be https; test.
- The lab scenarios were rewritten for v0.8: `fleet` waits for the link to adopt the node's users by itself (`auto_import`, `node.import` in the audit) and checks that a manual import is idempotent; `ui` waits for the policy to load after an exit probe and removes the rule/exit through the API rather than by clicking the table.
