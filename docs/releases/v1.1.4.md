# v1.1.4 — выдача любого числа доступов и живой статус узлов

[English](#english) · **Русский**

Дата: 2026-10-12. Предыдущий выпуск: [v1.1.3](https://github.com/dubr1k/proxy-control/releases/tag/v1.1.3).

## Русский

### Что изменилось

- **Выдача «все протоколы на всех узлах» больше не падает.** Один запрос принимал не больше 8 доступов, а три протокола на четырёх узлах дают 12; панель отвечала 422, а клиент оставался без доступов. Ограничение снято.
- **«Ожидает узел» не висит после подтверждения.** Список клиентов перечитывается сам с растущими паузами (около двух минут), пока какой-либо доступ ждёт узел, и показывает подтверждение без перезагрузки страницы.

Миграций базы и изменений протокола Fleet нет. Менеджеры протоколов и логика установщика не менялись. Скрипт установки в приложенных файлах привязан к версии 1.1.4 и контрольной сумме её архива.

### Установка на новый сервер

Требования: Ubuntu 24.04 LTS x86-64, собственные DNS-имена и обычный пользователь с `sudo`. Не запускайте мастер непосредственно от root. Подробно — [установка](https://github.com/dubr1k/proxy-control/blob/v1.1.4/README.md#установка-человеком) и [справочник](https://github.com/dubr1k/proxy-control/blob/v1.1.4/docs/INSTALLER_REFERENCE.ru.md).

В пустом рабочем каталоге скачайте файлы **именно v1.1.4**:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.1.4/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.1.4/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Продолжайте только после успешной проверки SHA-256. Мастер спросит домены и состав установки; на одном сервере с существующим Nginx/3x-ui выбирайте соответствующий режим сосуществования.

### Обновление существующей установки

Сначала сделайте [резервную копию](https://github.com/dubr1k/proxy-control/blob/v1.1.4/docs/BACKUP_RESTORE.ru.md). Скачайте и проверьте два файла командами выше, затем вместо запуска мастера выполните:

```bash
bash install-release.sh --update
```

В парке связанных панелей штатный порядок — узлы, затем центр. После обновления проверьте состояние служб и обновите подписку в клиентском приложении. Не удаляйте контейнерные тома, базу или секреты ради обновления.

### Ограничение проверки выпуска

Выпуск проверен автоматическими тестами затронутых областей, без нового полного установочного прогона. Поведение списка клиентов в браузере проверьте при первой выдаче доступов.

## English

### Changes

- **Issuing «all protocols on all nodes» no longer fails.** One request accepted at most 8 accesses, while three protocols on four nodes make 12; the panel answered 422 and left the client without accesses. The cap is gone.
- **«Waiting for the node» no longer lingers after confirmation.** The client list re-reads itself with growing pauses (about two minutes) while any access waits for its node, so the confirmation shows without a page reload.

There are no database migrations or Fleet protocol changes. Protocol managers and installer logic are unchanged. The attached installation script is stamped with version 1.1.4 and its archive digest.

### Fresh installation

Use Ubuntu 24.04 LTS x86-64 and a regular user with `sudo`, not a root login. Prepare your DNS names and follow the [installation guide](https://github.com/dubr1k/proxy-control/blob/v1.1.4/README.en.md#installation-by-a-human) and [installer reference](https://github.com/dubr1k/proxy-control/blob/v1.1.4/docs/INSTALLER_REFERENCE.en.md).

In an empty working directory:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.1.4/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.1.4/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Continue only after checksum verification succeeds. The wizard asks for domains and components. Select the appropriate coexistence mode when Nginx/3x-ui is already installed.

### Upgrading

Make a [backup](https://github.com/dubr1k/proxy-control/blob/v1.1.4/docs/BACKUP_RESTORE.en.md), download and verify the same files, then run:

```bash
bash install-release.sh --update
```

The normal fleet update order is nodes first, central panel last. Check service health afterwards and refresh the existing subscription. Do not delete Docker volumes, the database or secrets as part of an update.

### Validation limitation

This release is checked by automated tests of the touched areas, without a new full installer acceptance run. Check the client list behaviour in the browser on your first issue of accesses.
