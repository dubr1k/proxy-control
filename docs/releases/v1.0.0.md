## Русский

### Добавлено

- **Понятная маршрутизация.** Экран разбит на четыре шага в порядке работы: для кого → куда идёт трафик → проверить → применить на узле, у каждого шага короткое пояснение. Возможности сервиса написаны словами («блокировать домены», «отдельные сайты — в другой выход») вместо кодов. Выходы, Xray-router, списки geosite/geoip и relay собраны в сворачиваемый блок «Возможности узла», а технические детали проверки — под короткой сводкой: «по умолчанию трафик идёт через WARP; исключений: 2».
- **Инструкция прямо в панели.** Кнопка «Как это работает» на экране маршрутизации: термины, что умеет каждый сервис, восемь пошаговых сценариев с кнопкой «Начать» — весь трафик через WARP, отдельные сайты через WARP, реклама, торренты, российские сайты напрямую, выход через другой узел, свой VPN или прокси, отдельный маршрут одному клиенту, — разница между «Сохранить» и «Применить» и что делать, если проверка говорит «не применимо». Сценарий только готовит черновик: на узел ничего не уходит без «Сохранить» и «Применить».
- **Английский интерфейс.** Переключатель RU/EN в шапке и на странице входа, выбор запоминается в браузере. Переведены все экраны, диалоги и уведомления; даты и числа — в формате выбранного языка.
- **Ключи Mieru не нужно ротировать, чтобы показать снова.** Панель сохраняет в своём зашифрованном хранилище каждый ключ Mieru, который выдаёт сама: при создании и по кнопке «Новый ключ». Кнопка «Конфигурация» на странице Mieru показывает текущий ключ снова, на узле при этом ничего не меняется и старая ссылка продолжает работать. Если клиент на своей полосе маршрутизации, ссылка ведёт на порт его слота. Пользователи, выданные раньше, помечены «Ключ не сохранён»: mita хранит только хэш пароля, поэтому для них один раз нажмите «Новый ключ» — дальше ключ сохраняется. Бывшая кнопка «Новая ссылка + QR» теперь называется «Новый ключ».
- **Throne (бывший Nekoray).** Throne берёт NaiveProxy и Mieru из варианта подписки «sing-box JSON для Karing и Throne» и ничего не импортирует из Clash YAML. Это теперь написано в окне клиента, у доступов появилась отметка `throne`, а в матрице совместимости — колонка Throne. Ограничение Throne 1.3.1: Mieru по UDP подключается, только если сервер указан IP-адресом, по TCP — всегда.
- **Swap на «Обзоре».** Под строкой «Оперативная память» показан swap: занято, всего и полоска, либо «выключен на сервере».
- **Акцентный цвет.** Кнопка-палитра в шапке, семь вариантов. Выбор запоминается в браузере и работает и на телефоне.

### Исправлено

- **Подписка отдавала заменённый пароль.** Создание и ротация на страницах Mieru и NaiveProxy шли мимо хранилища панели, и подписка клиента продолжала отдавать пароль, который узел уже не принимал. Теперь новый пароль сразу попадает в подписку. Если вы ротировали доступ на этих страницах раньше, выпустите новый ключ ещё раз — подписка его подхватит.
- **Удаление оставляло доступ в карточке клиента.** Удаление на страницах Mieru и NaiveProxy теперь убирает и запись доступа, со своей полосой маршрутизации, если она была.
- **Карточка клиента.** Доступы выстроены таблицей с общими колонками: протокол · аккаунт · состояние · маршрут · действия. Порядок протоколов везде одинаковый: MTProxy → Naive → Mieru. У состояния цветная точка. Кнопка маршрута называет действие: «Выделить полосу» / «Вернуть общий». Архивные клиенты идут в конце списка. На телефоне имя клиента больше не уезжает к правому краю, а кнопки выстроены сеткой.
- **«Обзор» при загрузке больше не прыгает.** Заглушка повторяет настоящую раскладку — ресурсы сервера и три карточки протоколов, — а не ряд из трёх или четырёх плиток.

## English

### Added

- **Clear routing.** The screen is four steps in working order — for whom → where traffic goes → check → apply on the node — each with a short explanation. A service's capabilities are named in words («block domains», «some sites to another exit») instead of codes. Exits, the Xray-router, geosite/geoip lists and the relay sit in a folded «Возможности узла» (node capabilities) block, and the check's technical details under a short summary: «by default traffic goes through WARP; exceptions: 2».
- **A guide inside the panel.** «Как это работает» (How it works) on the routing screen: the terms, what each service can do, eight step-by-step scenarios with a Start button — all traffic through WARP, some sites through WARP, ads, torrents, Russian sites direct, an exit through another node, your own VPN or proxy, one client's own route — Save versus Apply, and what to do when the check says it cannot be applied. A scenario only prepares the draft: nothing reaches a node without Save and Apply.
- **English interface.** An RU/EN switch in the header and on the sign-in page, remembered per browser. Every screen, dialog and notification is translated; dates and numbers follow the chosen language.
- **Mieru keys no longer need a rotation to be shown again.** The panel keeps every Mieru key it issues itself — on create and on «Новый ключ» (New key) — in its encrypted store. «Конфигурация» (Configuration) on the Mieru page shows the current key again; nothing changes on the node and the old link keeps working. A client on its own routing lane gets its slot's port. Users issued earlier are marked «Ключ не сохранён» (key not kept): mita holds only a hash of the password, so press «Новый ключ» once for them and the key is kept from then on. The former «Новая ссылка + QR» button is now «Новый ключ».
- **Throne (formerly Nekoray).** Throne takes NaiveProxy and Mieru from the «sing-box JSON для Karing и Throne» subscription variant and imports nothing from Clash YAML. The client window says so, grants carry a `throne` mark, and the compatibility matrix has a Throne column. Throne 1.3.1 limitation: Mieru over UDP connects only when the server is an IP address; TCP always works.
- **Swap on the overview.** The RAM row shows swap — used, total and a bar — or «выключен на сервере» when the server has none.
- **Accent colour.** A palette button in the header with seven accents, remembered per browser, also on a phone.

### Fixed

- **A subscription served the replaced password.** Creating and rotating on the Mieru and NaiveProxy pages bypassed the panel's store, so a client's subscription kept serving a password the node no longer accepted. The new password now reaches the subscription at once. If you rotated on those pages before, issue a new key once more and the subscription will pick it up.
- **Deleting left the grant on the client card.** Deleting on the Mieru and NaiveProxy pages now removes the grant too, together with its own routing lane if it had one.
- **Client card.** Grants line up as a table with shared columns — protocol · account · state · route · actions — in one order everywhere, MTProxy → Naive → Mieru, with a coloured state dot. The route button names the action. Archived clients go last. On a phone the client's name no longer drifts to the right edge and the buttons sit in a grid.
- **The overview no longer jumps while loading.** The placeholder has the real layout — server resources and three protocol cards — instead of a row of three or four tiles.
