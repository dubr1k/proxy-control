# v1.3.3 — AmneziaWG на хосте, который установщик не ставил

[English](#english) · **Русский**

Дата: 2026-10-17. Предыдущий выпуск: [v1.3.2](https://github.com/dubr1k/proxy-control/releases/tag/v1.3.2).

## Русский

### Что изменилось

- **Поддерживаемый способ включить AmneziaWG на хосте, установленном вручную.** Скрипт `scripts/enable-amneziawg.sh` из распакованного выпуска делает то же, что шаг AmneziaWG установщика, и безопасен при повторном запуске: копирует менеджер и оверлей, создаёт токен и каталог состояния (ключи сервера не затрагиваются), включает пересылку IPv4, открывает порты и пересылку в `ufw` (без `ufw` ставит `awg-forward.service`), добавляет оверлей в список версионного агента и проверяет все версии. Описан в `AMNEZIAWG.ru.md`.
- Остальное без изменений: миграций базы нет, протокол Fleet и установщик не менялись.

### Установка на новый сервер

Требования: Ubuntu 24.04 LTS x86-64, собственные DNS-имена и обычный пользователь с `sudo`. Не запускайте мастер непосредственно от root. Подробно — [установка](https://github.com/dubr1k/proxy-control/blob/v1.3.3/README.md#установка-человеком) и [справочник](https://github.com/dubr1k/proxy-control/blob/v1.3.3/docs/INSTALLER_REFERENCE.ru.md).

В пустом рабочем каталоге скачайте файлы **именно v1.3.3**:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.3.3/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.3.3/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Продолжайте только после успешной проверки SHA-256. Мастер спросит домены и состав установки; на одном сервере с существующим Nginx/3x-ui выбирайте соответствующий режим сосуществования.

### Обновление существующей установки

Сначала сделайте [резервную копию](https://github.com/dubr1k/proxy-control/blob/v1.3.3/docs/BACKUP_RESTORE.ru.md). Скачайте и проверьте два файла командами выше, затем вместо запуска мастера выполните:

```bash
bash install-release.sh --update
```

В парке связанных панелей штатный порядок — узлы, затем центр. После обновления проверьте состояние служб и обновите подписку в клиентском приложении. Не удаляйте контейнерные тома, базу или секреты ради обновления.

### Ограничение проверки выпуска

Выпуск проверен автоматическими тестами затронутых областей, без нового полного установочного прогона. Скрипт нужен только хосту, который установщик не ставил.

## English

### Changes

- **A supported way to enable AmneziaWG on a hand-installed host.** The script `scripts/enable-amneziawg.sh` from the unpacked release does what the installer's AmneziaWG step does and is safe to repeat: it copies the manager and the overlay, creates the token and the state directory (the server keys are never touched), turns on IPv4 forwarding, opens the ports and forwarding in `ufw` (without `ufw` it installs `awg-forward.service`), adds the overlay to the version agent's list and checks every version. Described in `AMNEZIAWG.en.md`.
- Everything else is unchanged: no database migrations, and the Fleet protocol and the installer did not change.

### Fresh installation

Use Ubuntu 24.04 LTS x86-64 and a regular user with `sudo`, not a root login. Prepare your DNS names and follow the [installation guide](https://github.com/dubr1k/proxy-control/blob/v1.3.3/README.en.md#installation-by-a-human) and [installer reference](https://github.com/dubr1k/proxy-control/blob/v1.3.3/docs/INSTALLER_REFERENCE.en.md).

In an empty working directory:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.3.3/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v1.3.3/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Continue only after checksum verification succeeds. The wizard asks for domains and components. Select the appropriate coexistence mode when Nginx/3x-ui is already installed.

### Upgrading

Make a [backup](https://github.com/dubr1k/proxy-control/blob/v1.3.3/docs/BACKUP_RESTORE.en.md), download and verify the same files, then run:

```bash
bash install-release.sh --update
```

The normal fleet update order is nodes first, central panel last. Check service health afterwards and refresh the existing subscription. Do not delete Docker volumes, the database or secrets as part of an update.

### Validation limitation

This release is checked by automated tests of the touched areas, without a new full installer acceptance run. The script is only for a host the installer did not set up.
