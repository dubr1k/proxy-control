## Русский

### Добавлено

- **Скрипт установки рядом с архивом.** В каждом выпуске теперь лежат `install-release.sh` и `install-release.sh.sha256`. Это тот же `scripts/install-release.sh`, в который сборка записала версию и SHA-256 архива своего выпуска. Скачайте оба файла, сверьте сумму, прочитайте скрипт и запустите обычным пользователем:

  ```bash
  curl -fsSLO https://github.com/dubr1k/proxy-control/releases/latest/download/install-release.sh
  curl -fsSLO https://github.com/dubr1k/proxy-control/releases/latest/download/install-release.sh.sha256
  sha256sum --check install-release.sh.sha256
  bash install-release.sh
  ```

  Скрипт скачивает четыре файла выпуска, сверяет `SHA256SUMS`, манифест и записанный в нём digest архива. Подменённый архив он не распакует, даже если вместе с архивом подменён и `SHA256SUMS`. При наличии `gh` скрипт проверяет attestation, затем распаковывает выпуск и одним `sudo` запускает мастер. На сам скрипт тоже выпускается attestation: `gh attestation verify install-release.sh --repo dubr1k/proxy-control`. Можно ограничиться проверкой: `--requirements` печатает требования к хосту, `--check-only` только скачивает и проверяет, `--no-wizard` ещё и распаковывает, но мастер не запускает.
- **Пояснения и значения по умолчанию в мастере.** Перед выбором режима сервера, профиля и режима 3x-ui мастер в одной строке объясняет каждый вариант. Enter принимает обычный случай: `fresh`, `full`, без 3x-ui. Для портов Mieru предлагается `46001`.

### Исправлено

- **Пароли, введённые в мастере, не доходили до установки.** Если сразу выбрать «apply», пароль панели и логин с паролем 3x-ui молча заменялись сгенерированными; сохранялись они только при «save» с последующим `install --config`. Теперь мастер передаёт их установке во временной приватной копии, которая стирается сразу после установки.
- **Вопрос «Первый пользователь» вводил в заблуждение.** Это имя первого пользователя MTProxy и Mieru, а логин в панель всегда `owner`. Теперь вопрос так и звучит, а пароль спрашивается как «пароль для входа в панель под owner».
- **Домены WARP для 3x-ui.** Подсказка обещала «пусто — нет», а пустой ответ не принимался, и мастер зацикливался. Теперь подсказка требует хотя бы один домен и принимает `geosite:`-списки и `domain:`-селекторы — так же, как файл конфигурации.
- **Порты Mieru.** Порт 8443 (TLS-хост панели), WARP, порты Xray-router, слоты полос и другие порты, которые установщик занимает сам, больше не проходят проверку. Раньше установка спотыкалась о занятый порт уже на хосте; теперь мастер сразу называет порт и чем он занят. Порты ниже 1024 мастер не принимает, как и файл конфигурации.
- **Ошибка в конфигурации называет причину.** Раньше было «исправьте отмеченные поля», хотя ничего отмечено не было.
- **3x-ui в режиме `coexist` и `existing`.** `managed-new`, который план на таком хосте всё равно отверг бы, в режиме `coexist` больше не предлагается. В режиме `existing` мастер спрашивает только домены VLESS Reality TCP и XHTTP (маршруты строятся только к ним) и требует хотя бы один. Домены панели и Hysteria2 там не использовались, но их DNS-проверка могла остановить установку.
- **Мелочи:**
  - сводка перед установкой показывает только то, что эта установка использует;
  - «Изменения не внесены» печатается один раз;
  - логин 3x-ui сохраняется и при сгенерированном пароле;
  - домен подписки 3x-ui проверяется на совпадение с другими доменами общего 443.

### Обновление с v1.0.2

Работающим установкам ничего делать не нужно: панель не менялась. Если хотите, чтобы на «Версиях» была последняя версия, — «Версии» → карточка «Proxy Control / панель» → `1.0.3` → «Установить»; менеджеры пересобирать не нужно.

## English

### Added

- **The install script beside the archive.** Every release now carries `install-release.sh` and `install-release.sh.sha256` — the same `scripts/install-release.sh` with its release's version and archive SHA-256 written in by the build. Download both, check the sum, read the script, run it as a regular user:

  ```bash
  curl -fsSLO https://github.com/dubr1k/proxy-control/releases/latest/download/install-release.sh
  curl -fsSLO https://github.com/dubr1k/proxy-control/releases/latest/download/install-release.sh.sha256
  sha256sum --check install-release.sh.sha256
  bash install-release.sh
  ```

  It downloads the four release files and checks `SHA256SUMS`, the manifest and the archive digest written into it. A swapped archive is not extracted, even when `SHA256SUMS` was swapped along with it. With `gh` present it verifies the attestation, then extracts the release and starts the wizard through one `sudo`. The script itself is attested too: `gh attestation verify install-release.sh --repo dubr1k/proxy-control`. To stop short of installing: `--requirements` prints what the host needs, `--check-only` downloads and verifies only, `--no-wizard` also extracts but does not start the wizard.
- **Explanations and defaults in the wizard.** Before asking for the host mode, the profile and the 3x-ui mode the wizard explains each option in a line. Enter takes the common case: `fresh`, `full`, no 3x-ui. The Mieru ports default to `46001`.

### Fixed

- **Passwords typed in the wizard did not reach the installation.** With «apply» straight from the wizard, the panel password and the 3x-ui username and password were silently replaced by generated ones; only «save» followed by `install --config` kept them. The wizard now hands them to the installation in a private temporary copy, erased as soon as the installation ends.
- **The «Initial user» question was misleading.** It is the name of the first MTProxy and Mieru user; the panel login is always `owner`. The question now says so, and the password is asked as the password to sign in to the panel as owner.
- **WARP domains for 3x-ui.** The prompt promised «blank for none», but a blank answer was refused and the wizard looped. The prompt now asks for at least one domain and accepts `geosite:` lists and `domain:` selectors, exactly as the configuration file does.
- **Mieru ports.** Port 8443 (the panel's TLS host), the WARP port, the Xray-router ports, lane slots and the other ports the installer binds itself no longer pass. The installation used to stumble on the taken port on the host; now the wizard names the port and what takes it. Ports below 1024 are refused, as in the configuration file.
- **An invalid configuration says why,** instead of «edit the highlighted fields» with nothing highlighted.
- **3x-ui with `coexist` and `existing`.** `managed-new`, which the plan would refuse on such a host anyway, is no longer offered in `coexist` mode. In `existing` mode the wizard asks only for the VLESS Reality TCP and XHTTP domains (the only ones routed) and needs at least one. The panel and Hysteria2 domains were unused there, but their DNS check could stop the installation.
- **Small things:**
  - the review before installing lists only what this installation uses;
  - «No changes were made» is printed once;
  - a 3x-ui username is kept even with a generated password;
  - the 3x-ui subscription domain is checked against the other shared-443 domains.

### Upgrading from v1.0.2

Running installations need nothing: the panel did not change. To have the latest version on the Versions screen: Versions → the «Proxy Control / панель» card → `1.0.3` → «Установить» (Install); no manager needs a rebuild.
