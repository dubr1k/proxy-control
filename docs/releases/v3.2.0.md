# v3.2.0 — версии AmneziaWG и TrustTunnel с экрана «Версии»

[English](#english) · **Русский**

Дата: 2026-10-20. Предыдущий выпуск: [v3.1.0](https://github.com/dubr1k/proxy-control/releases/tag/v3.1.0).

## Русский

### Что нового

- **AmneziaWG и TrustTunnel на экране «Версии».** Раньше версии amneziawg-go и endpoint TrustTunnel были зашиты в выпуск, и сменить их можно было только вместе с новой версией панели. Теперь у каждого своя карточка: текущая версия, «Проверить обновления», список новых выпусков и откат на прежние. Как и у остальных компонентов, ставить может только владелец.
  - **AmneziaWG**: теги проекта `amnezia-vpn/amneziawg-go`. Ставится ровно тот коммит, на который указывает тег, и после сборки сверяется.
  - **TrustTunnel**: стабильные выпуски `TrustTunnel/TrustTunnel` с контрольной суммой, которую опубликовал GitHub. Бета-версии не предлагаются. Выпуск без опубликованной суммы виден, но не ставится.
- **Как проходит смена версии.** Агент пересобирает образ менеджера с выбранной версией и перезапускает только этот менеджер. Затем он проверяет, что менеджер здоров и работает именно на новой версии. При любой ошибке возвращаются прежний образ и прежние настройки, и агент убеждается, что снова работает старая версия. Туннели AmneziaWG и сессии TrustTunnel обрываются на несколько секунд, приложения переподключаются сами. Ключи, пароли и счётчики доступов не трогаются.
- **Версия держится.** Выбранная версия записывается в переопределения версий хоста. Следующее обновление панели, обновление сервера одной командой и `repair` установщика собирают менеджер с ней, а не возвращают версию из выпуска.
- **Карточка «Proxy Control / панель» — первая.** Дальше карточки идут в порядке обзора: Telemt, Mieru, AmneziaWG, TrustTunnel, NaiveProxy, Xray-router. Узлы флота тоже показывают и обновляют AmneziaWG и TrustTunnel: «Узлы» → узел → «Обновления».

### Что важно знать

- Карточки появляются только на сервере, где протокол установлен.
- Готовый выпуск TrustTunnel есть для x86-64, поэтому на сервере другой архитектуры агент откажет до любых изменений.
- Обновление пересобирает панель и менеджер AmneziaWG: образ менеджера теперь хранит свою версию amneziawg-go, сама версия не меняется. После обновления из интерфейса агент сам пересобирает менеджеры, как раньше.
- **Установщик:** адаптеры AmneziaWG и TrustTunnel собирают менеджеры вместе с переопределениями версий хоста, а при удалении протокола убирают из них его запись. Вопросы мастера, конфигурация и пины не менялись.
- **Обновляетесь с 2.x?** Сначала прочитайте заметки [v3.0.0](https://github.com/dubr1k/proxy-control/releases/tag/v3.0.0) и [v3.0.1](https://github.com/dubr1k/proxy-control/releases/tag/v3.0.1). Это обновление переименует стек Docker из `mtproxy` в `proxy_panel_by_dubr1k`, службы встанут меньше чем на минуту.

### Новая установка

Используйте Ubuntu 24.04 LTS x86-64 и обычного пользователя с `sudo`, не вход под root. Подготовьте DNS-имена и следуйте [руководству по установке](https://github.com/dubr1k/proxy-control/blob/v3.2.0/README.md#установка-человеком) и [справочнику установщика](https://github.com/dubr1k/proxy-control/blob/v3.2.0/docs/INSTALLER_REFERENCE.ru.md).

В пустом рабочем каталоге:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v3.2.0/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v3.2.0/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Продолжайте только после успешной проверки контрольной суммы.

### Обновление

Сделайте [резервную копию](https://github.com/dubr1k/proxy-control/blob/v3.2.0/docs/BACKUP_RESTORE.ru.md), скачайте и проверьте те же файлы, затем выполните:

```bash
bash install-release.sh --update
```

Можно и с экрана «Версии» → «Proxy Control / панель». Порядок обновления флота прежний: сначала узлы, центральная панель последней. Тома Docker, базу и секреты при обновлении не удаляйте. Подробнее: [обновление](https://github.com/dubr1k/proxy-control/blob/v3.2.0/docs/UPGRADING.ru.md).

## English

### What's new

- **AmneziaWG and TrustTunnel on the «Versions» screen.** The amneziawg-go and TrustTunnel endpoint versions used to be fixed by the release, so they changed only with a new panel version. Each now has its own card: the current version, «Check for updates», newer releases and a way back to earlier ones. As with every other component, only the owner can install.
  - **AmneziaWG**: the tags of `amnezia-vpn/amneziawg-go`. Exactly the commit the tag points at is built and checked after the build.
  - **TrustTunnel**: stable releases of `TrustTunnel/TrustTunnel` with the checksum GitHub published. Betas are not offered. A release without a published checksum is visible but not installable.
- **How a version change runs.** The agent rebuilds the manager's image with the chosen version and restarts only that manager. It then checks that the manager is healthy and runs exactly the new version. On any error the previous image and settings come back, and the agent makes sure the old version runs again. AmneziaWG tunnels and TrustTunnel sessions drop for a few seconds and the apps reconnect by themselves. Keys, passwords and access counters are not touched.
- **The version holds.** The chosen version is written to the host's version overrides. The next panel update, the one-command server update and the installer's `repair` build the manager with it instead of putting the release's version back.
- **The «Proxy Control / panel» card comes first.** The other cards follow the overview's order: Telemt, Mieru, AmneziaWG, TrustTunnel, NaiveProxy, Xray-router. Fleet nodes show and update AmneziaWG and TrustTunnel too: «Nodes» → node → «Updates».

### Good to know

- The cards appear only on a server where the protocol is installed.
- TrustTunnel publishes a ready release for x86-64 only, so on a server of another architecture the agent refuses before changing anything.
- The update rebuilds the panel and the AmneziaWG manager: the manager's image now records its amneziawg-go version; the version itself does not change. After an update from the interface the agent rebuilds the managers itself, as before.
- **Installer:** the AmneziaWG and TrustTunnel adapters build the managers together with the host's version overrides and, when a protocol is removed, drop its entry from them. The wizard questions, the configuration and the pins did not change.
- **Updating from 2.x?** Read the notes of [v3.0.0](https://github.com/dubr1k/proxy-control/releases/tag/v3.0.0) and [v3.0.1](https://github.com/dubr1k/proxy-control/releases/tag/v3.0.1) first. This update renames the Docker stack from `mtproxy` to `proxy_panel_by_dubr1k`; the services stop for under a minute.

### Fresh installation

Use Ubuntu 24.04 LTS x86-64 and a regular user with `sudo`, not a root login. Prepare your DNS names and follow the [installation guide](https://github.com/dubr1k/proxy-control/blob/v3.2.0/README.en.md#installation-by-a-human) and [installer reference](https://github.com/dubr1k/proxy-control/blob/v3.2.0/docs/INSTALLER_REFERENCE.en.md).

In an empty working directory:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v3.2.0/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v3.2.0/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Continue only after checksum verification succeeds.

### Upgrading

Make a [backup](https://github.com/dubr1k/proxy-control/blob/v3.2.0/docs/BACKUP_RESTORE.en.md), download and verify the same files, then run:

```bash
bash install-release.sh --update
```

The «Versions» screen → «Proxy Control / panel» works too. The fleet update order is unchanged: nodes first, central panel last. Do not delete Docker volumes, the database or secrets as part of an update. More: [upgrading](https://github.com/dubr1k/proxy-control/blob/v3.2.0/docs/UPGRADING.md).
