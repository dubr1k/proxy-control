## Русский

### Что изменилось для вас

**Кнопка «Проверить обновления».** На экране «Версии» больше не нужно вручную вести
`versions.json`: панель просит агента спросить у самих проектов, что вышло. Для Xray-core, Mieru
и Caddy это GitHub Releases, для Telemt — реестр образов. Версии новее установленной появляются в
списке с пометкой «upstream» и хэшем из релиза; каталог оператора остаётся и помечен «каталог».

**Что значит пометка «upstream».** Хэш из релиза подтверждает, что файл скачан без искажений и
совпадает с тем, что выложил автор проекта. Он не подтверждает, что версия проверена на нашем
стенде. Это честная пометка, а не предупреждение об опасности: обновляйтесь, когда готовы
проверить сервис после установки; при любой ошибке агент вернёт прежнюю версию сам.

**Xray-router обновляется из панели.** Если роутер установлен, на экране «Версии» появляется
карточка «Xray-router / Xray-core»: выбираете версию — агент ставит `xray`, `geoip.dat` и
`geosite.dat` из релиза, пересоздаёт роутер и проверяет, что он запустился с новой версией.
Установщик знает о таком обновлении и не считает его поломкой.

**NaiveProxy обновляется тоже.** Готового бинарника Caddy с forward-proxy в upstream нет, поэтому
агент собирает его на хосте из builder-образа Caddy и модуля forwardproxy. Сборка занимает до
15 минут, кнопка показывает «Собираем…».

**Mieru обновляется без обходных путей.** Раньше обновление `mita` отказывало, пока существует
контейнер менеджера. Теперь агент сам переписывает его пин и пересоздаёт менеджер.

**Панель обновляет сама себя.** На экране «Версии» появилась карточка «Proxy Control / панель»:
агент показывает свежие релизы проекта, а по кнопке сам переносит файлы релиза в каталог проекта,
пересобирает и перезапускает панель и проверяет, что она отвечает новой версией. Страница перезагрузится
сама. Секреты и настройки не трогаются; прежние файлы, база данных и образ сохраняются, и при любой ошибке
агент возвращает прежнюю версию. Если в релизе изменились менеджеры протоколов, карточка попросит
пересобрать их по [UPGRADING](../UPGRADING.ru.md#обновление-самой-панели-из-ui).

**Агент версий ставит установщик.** На свежей установке экран «Версии» больше не пуст: установщик
сам кладёт код агента, unit и env с overlay'ями вашего профиля, создаёт пустой каталог и записывает
в state версии, которые только что поставил, — Telemt, Caddy, mita и Xray-core, если роутер включён.
Хостам, установленным раньше, по-прежнему нужны ручные шаги из [UPGRADING](../UPGRADING.ru.md).

**Обзор компактнее.** «Ресурсы сервера» — одной строкой на всю ширину, три протокола под ней;
у Mieru нет больше бессмысленного «Application bytes»; бейдж «Клиенты» в меню показывает общее
число клиентов. На телефоне всё в одну колонку.

**MCP-сервер для Claude Code и Claude Desktop.** На центральной панели можно поднять контейнер
`proxy-control-mcp`: модель получает инструменты панели — обзор, создание клиента с матрицей
узел×протокол и ссылкой подписки, проверку и установку обновлений, предпросмотр и применение
маршрутизации, хвост аудита и всё остальное из API. Необратимые действия требуют `confirm: true`,
каждый вызов идёт через API-ключ `mcp` и виден в аудите. Домен MCP — одиннадцатый вопрос мастера;
подключение: `claude mcp add --transport http proxy-control https://<домен>/mcp --header "Authorization: Bearer …"`
([docs/MCP.ru.md](../MCP.ru.md)).

**Мелочи интерфейса.** Карточка клиента получила кнопку «Узлы и доступы» — окно открывается сразу
на матрице «узел × протокол». В том же окне переключатели «Вариант ссылки под клиента» стоят у
левого края обычного размера, а не растянутые по центру строки. Доступ на связанный узел, который
узел ещё не доставил, показывается тостом «Отправлено узлу: доступ появится после доставки», а не
красным `pending_remote`. Второстепенные кнопки («Проверить обновления», «Включить», «Ротировать»)
оформлены как остальные, а не рамкой браузера по умолчанию. Кнопки добавления — «+ Клиент» и
«+ Администратор».

### Установка с нуля

Нужен VPS на x86-64 с Ubuntu 24.04, root через `sudo`, домены с A-записями на этот сервер (сколько и
каких — [README, «Домены и сертификаты»](../../README.md#домены-и-сертификаты)) и открытые 80/443.
Проект не предлагает «скачать и выполнить одной командой»: файлы сначала попадают на диск и
проверяются.

1. Со страницы выпуска на GitHub скачайте четыре файла из Assets: `proxy-control-v0.11.0-beta.1.tar.gz`,
   `SHA256SUMS`, `release-manifest.json`, `sbom.spdx.json` — в один новый каталог.
2. Сверьте суммы и распакуйте архив (`install-bootstrap` внутри архива отказывает версии с
   prerelease-суффиксом, поэтому бета ставится мастером из распакованного каталога):

   ```bash
   sha256sum --check SHA256SUMS
   tar -xzf proxy-control-v0.11.0-beta.1.tar.gz
   cd proxy-control
   sudo python3 -m installer.cli wizard
   ```

   Те же шаги одной командой делает `scripts/install-release.sh` из клона репозитория: он скачивает
   четыре файла, сверяет `SHA256SUMS` и манифест, при `--sha256` — закреплённый digest архива, при
   наличии `gh` — attestation, распаковывает и передаёт управление мастеру:

   ```bash
   scripts/install-release.sh --requirements
   scripts/install-release.sh --version 0.11.0-beta.1 --sha256 <sha256 архива из блока «Архив» выше>
   ```

3. Ответьте на вопросы мастера: язык, режим сервера (`fresh` или `coexist` с уже стоящим Nginx),
   профиль (`core`, `full` и др.), режим 3x-ui (`none` — не трогать, `existing` — принять уже
   стоящий и разделить с ним порт 443, `managed-new` — поставить самому), домены — панель, MTProxy,
   NaiveProxy, Mieru, при 3x-ui ещё пять, домен подписки клиентов и домен MCP-сервера (пусто —
   выключено; нужен только на центральной панели), e-mail для Let's Encrypt, WARP, Xray-router.
   Полный список с пояснениями — [README, «Шаг 2»](../../README.md#шаг-2-ответьте-на-вопросы-мастера).
   Мастер пишет обычный TOML.
4. Посмотрите план и подтвердите его digest — до этого установщик ничего не меняет. Дождитесь
   приёмки: он поднимет контейнеры, выпустит сертификаты, в режиме `managed-new` сам поставит 3x-ui
   `3.7.0` с инбаундами VLESS Reality TCP, VLESS Reality XHTTP и Hysteria2 и маршрутами Nginx для его
   доменов, установит `version-agent` и, если задан домен, MCP-сервер; отчёт, пароль первого входа и
   доступ к панели 3x-ui — в его выводе.
5. Откройте панель по её домену, войдите владельцем и смените пароль. Адрес и токен MCP лежат в
   root-only handoff установщика; подключение — `claude mcp add --transport http proxy-control
   https://<домен mcp>/mcp --header "Authorization: Bearer <токен>"` ([docs/MCP.ru.md](../MCP.ru.md)).

Если установка прервалась — `sudo python3 -m installer.cli repair` из того же каталога; удаление —
`uninstall.sh` там же ([README, «Повседневная работа»](../../README.md#повседневная-работа)).

### Обновление с v0.9 или v0.10

Как для любого выпуска без изменения базы относительно v0.10 (с v0.9 миграция 20 применится при
старте панели сама, [UPGRADING](../UPGRADING.ru.md#обновление-до-v010-подписка-под-рукой)). Все
команды — в каталоге проекта (`/opt/mtproxy-shared443` у установщика) с вашим набором overlay'ев:
`--env-file .env` плюс `.env.naive`, `.env.mieru`, `.env.xray-router`, если они есть, и `-f` для
каждого `compose.*.yaml` из них.

1. Сделайте резервную копию: `secrets/`, `.env*`, база панели (volume `mtproxy_panel-data`) и текущий
   образ панели (`docker tag mtproxy-panel:latest mtproxy-panel:rollback-<дата>`).
2. Скачайте и проверьте архив, как в шаге 1–2 выше, и перенесите в каталог проекта из распакованного
   `proxy-control/`: `panel/`, `installer/`, `scripts/`, `docker/`, `mieru_manager/`, `naive_manager/`,
   `xray_router_manager/`, `mcp_server/`, `release/`, `docs/`, `version_agent/`, `deploy/`,
   `compose*.yaml`, `VERSION`, `uninstall.sh`, `CHANGELOG*`, `README*`. **Не переносите** `secrets/`,
   `.env*`, `version-overrides/` и сертификаты. `VERSION` обновляйте именно в каталоге проекта — у
   установок через инсталлятор он смонтирован в контейнер.
3. Пересоберите панель и менеджер Mieru (он с этого выпуска принимает mita 3.35–3.37):

   ```bash
   docker compose --project-name mtproxy <ваши --env-file и -f> up -d --build --no-deps --wait panel mieru-manager
   docker exec proxy-control-panel cat /app/VERSION   # 0.11.0-beta.1
   ```

4. Обновите host-агент — код, unit и env ([UPGRADING](../UPGRADING.ru.md#обновления-из-upstream-v011)):

   ```bash
   sudo rsync -a --delete version_agent/ /opt/proxy-control/version_agent/
   sudo install -o root -g root -m 0644 deploy/version-agent.service /etc/systemd/system/version-agent.service
   sudo systemctl daemon-reload && sudo systemctl restart version-agent && systemctl is-active version-agent
   ```

   В `/etc/proxy-control/version-agent.env` замените `PROXY_CONTROL_PINNED_CONSUMERS` на
   `PROXY_CONTROL_CONSUMER_OVERLAYS=mita=<каталог проекта>/.env.mieru:MIERU_MITA_SHA256:mieru-manager`,
   при Xray-router добавьте `PROXY_CONTROL_XRAY_ROUTER=on`, затем ещё раз `systemctl restart version-agent`.
5. Нажмите «Проверить обновления» на экране «Версии». Если что-то не так — верните образ
   `mtproxy-panel:rollback-<дата>` тегом `latest` и пересоздайте панель; база после v0.10 не менялась.

MCP-сервер на уже стоящей установке — по [docs/MCP.ru.md](../MCP.ru.md): домен с A-записью,
сертификат, `.env.mcp`, секреты `secrets/mcp-token` и `secrets/mcp-panel-key` (ключ —
`docker compose … exec panel python -m panel.cli api-key-create --name mcp --scope admin`),
`compose.mcp.yaml` в наборе overlay'ев. Следующие выпуски ставятся кнопкой на карточке
«Proxy Control / панель».

Опрос upstream можно выключить: `PROXY_CONTROL_UPSTREAM_CHECK=off` — останется только каталог.

## English

### What changed for you

**«Проверить обновления».** The «Версии» screen no longer needs a hand-written `versions.json`:
the panel asks the agent to poll the projects themselves — GitHub Releases for Xray-core, Mieru
and Caddy, the image registry for Telemt. Versions newer than the installed one are listed as
«upstream» with the release's digest; the operator's catalog stays, marked «каталог».

**What «upstream» means.** The release digest proves the download is intact and identical to what
the project's author published. It does not prove the version was verified on our lab host. It is
an honest label, not a danger sign: update when you are ready to check the service afterwards; on
any failure the agent restores the previous version itself.

**The Xray-router updates from the panel.** With the router installed, «Версии» shows an
«Xray-router / Xray-core» card: pick a version and the agent installs `xray`, `geoip.dat` and
`geosite.dat` from the release, recreates the router and checks that it runs the new version.
The installer knows about such an update and does not treat it as drift.

**NaiveProxy updates too.** Upstream ships no Caddy binary with forward-proxy, so the agent builds
one on the host from the Caddy builder image and the forwardproxy module. The build takes up to
15 minutes; the button says «Собираем…».

**Mieru updates without workarounds.** A `mita` update used to refuse while the manager container
existed. The agent now rewrites its pin and recreates the manager itself.

**The panel updates itself.** The «Версии» screen gained a «Proxy Control / панель» card: the
agent lists the project's recent releases and, on request, copies the release's files into the
project directory, rebuilds and restarts the panel and checks that it answers with the new
version. The page reloads by itself. Secrets and settings are left alone; the previous files, the
database and the image are kept, and on any failure the agent restores the previous version. When
a release changed the protocol managers, the card asks you to rebuild them per
[UPGRADING](../UPGRADING.md#обновление-самой-панели-из-ui).

**The installer sets up the version-agent.** On a fresh install the «Версии» screen is no longer
empty: the installer copies the agent's code, installs the unit and an env with your profile's
overlays, seeds an empty catalog and records in the state the versions it just installed — Telemt,
Caddy, mita and Xray-core when the router is on. Hosts installed earlier still need the manual steps
in [UPGRADING](../UPGRADING.md).

**A tighter overview.** «Ресурсы сервера» as one full-width row with the three protocols under it;
the pointless Mieru «Application bytes» tile is gone; the «Клиенты» badge shows the total number
of clients. On a phone everything is one column.

**An MCP server for Claude Code and Claude Desktop.** The central panel can run a container
`proxy-control-mcp`: the model gets the panel's tools — the overview, creating a client with a
node×protocol matrix and its subscription link, checking and installing updates, previewing and
applying routing, the audit tail and everything else in the API. Irreversible actions require
`confirm: true`; every call goes through the `mcp` API key and shows in the audit log. The MCP domain
is the wizard's eleventh question; connect with `claude mcp add --transport http proxy-control https://<domain>/mcp --header "Authorization: Bearer …"`
([docs/MCP.en.md](../MCP.en.md)).

**Small things in the UI.** The client card gained a «Узлы и доступы» button — the window opens
straight on the node × protocol matrix. In that window the «Вариант ссылки под клиента» radios sit
at the left edge at their normal size instead of being stretched to the middle of the row. A grant
on a linked node that the node has not delivered yet shows as the toast «Отправлено узлу: доступ
появится после доставки», not as a red `pending_remote`. Secondary buttons («Проверить обновления»,
«Включить», «Ротировать») look like the rest instead of the browser default. The add buttons read
«+ Клиент» and «+ Администратор».

### Fresh install

You need an x86-64 VPS with Ubuntu 24.04, root through `sudo`, domains with A records pointing at
it (how many and which — [README, «Domains and certificates»](../../README.en.md#domains-and-certificates))
and ports 80/443 open. The project never offers «download and run in one command»: the files land
on disk first and are verified.

1. From the GitHub release page download the four Assets into one new directory:
   `proxy-control-v0.11.0-beta.1.tar.gz`, `SHA256SUMS`, `release-manifest.json`, `sbom.spdx.json`.
2. Check the sums and extract (`install-bootstrap` inside the archive refuses a pre-release
   suffix, so a beta is installed by the wizard from the extracted directory):

   ```bash
   sha256sum --check SHA256SUMS
   tar -xzf proxy-control-v0.11.0-beta.1.tar.gz
   cd proxy-control
   sudo python3 -m installer.cli wizard
   ```

   `scripts/install-release.sh` from a clone of the repository does the same in one command: it
   fetches the four files, checks `SHA256SUMS` and the manifest, with `--sha256` the pinned archive
   digest, with `gh` present the attestation, extracts and hands over to the wizard:

   ```bash
   scripts/install-release.sh --requirements
   scripts/install-release.sh --version 0.11.0-beta.1 --sha256 <archive sha256 from the «Archive» block above>
   ```

3. Answer the wizard: language, server mode (`fresh`, or `coexist` with an Nginx already there),
   profile (`core`, `full`, …), the 3x-ui mode (`none` — leave it alone, `existing` — adopt the one
   already installed and share port 443 with it, `managed-new` — install it), domains — the panel,
   MTProxy, NaiveProxy, Mieru, five more with 3x-ui, the client subscription domain and the MCP
   domain (empty — off; central panel only), the Let's Encrypt e-mail, WARP, the Xray-router. The
   full list with explanations — [README, «Step 2»](../../README.en.md#step-2-answer-the-wizard).
   The wizard writes plain TOML.
4. Review the plan and confirm its digest — nothing changes before that. Wait for the acceptance:
   the installer brings the containers up, issues the certificates, in `managed-new` mode installs
   3x-ui `3.7.0` itself with the VLESS Reality TCP, VLESS Reality XHTTP and Hysteria2 inbounds and
   the Nginx routes for its domains, installs the `version-agent` and, with a domain given, the MCP
   server; the report, the first-login password and the 3x-ui panel access are in its output.
5. Open the panel on its domain, log in as the owner and change the password. The MCP address and
   token are in the installer's root-only handoff; connect with `claude mcp add --transport http
   proxy-control https://<mcp domain>/mcp --header "Authorization: Bearer <token>"` ([docs/MCP.en.md](../MCP.en.md)).

If the install was interrupted — `sudo python3 -m installer.cli repair` from the same directory;
removal — `uninstall.sh` there ([README, «Day-to-day»](../../README.en.md#day-to-day-operation)).

### Upgrading from v0.9 or v0.10

As for any release without a database change relative to v0.10 (from v0.9, migration 20 applies
at panel start by itself, [UPGRADING](../UPGRADING.md#upgrading-to-v010-the-subscription-at-hand)).
Every command runs in the project directory (`/opt/mtproxy-shared443` for installer installs) with
your set of overlays: `--env-file .env` plus `.env.naive`, `.env.mieru`, `.env.xray-router` where
present, and `-f` for each matching `compose.*.yaml`.

1. Back up `secrets/`, `.env*`, the panel database (volume `mtproxy_panel-data`) and the current
   panel image (`docker tag mtproxy-panel:latest mtproxy-panel:rollback-<date>`).
2. Download and verify the archive as in steps 1–2 above and copy from the extracted
   `proxy-control/` into the project directory: `panel/`, `installer/`, `scripts/`, `docker/`,
   `mieru_manager/`, `naive_manager/`, `xray_router_manager/`, `mcp_server/`, `release/`, `docs/`,
   `version_agent/`, `deploy/`, `compose*.yaml`, `VERSION`, `uninstall.sh`, `CHANGELOG*`, `README*`.
   **Do not copy** `secrets/`, `.env*`, `version-overrides/` or certificates. Update `VERSION` in the
   project directory itself — installer installs mount it into the container.
3. Rebuild the panel and the Mieru manager (it now accepts mita 3.35–3.37):

   ```bash
   docker compose --project-name mtproxy <your --env-file and -f> up -d --build --no-deps --wait panel mieru-manager
   docker exec proxy-control-panel cat /app/VERSION   # 0.11.0-beta.1
   ```

4. Update the host agent — code, unit and env ([UPGRADING](../UPGRADING.md#updates-from-upstream-v011)):

   ```bash
   sudo rsync -a --delete version_agent/ /opt/proxy-control/version_agent/
   sudo install -o root -g root -m 0644 deploy/version-agent.service /etc/systemd/system/version-agent.service
   sudo systemctl daemon-reload && sudo systemctl restart version-agent && systemctl is-active version-agent
   ```

   In `/etc/proxy-control/version-agent.env` replace `PROXY_CONTROL_PINNED_CONSUMERS` with
   `PROXY_CONTROL_CONSUMER_OVERLAYS=mita=<project dir>/.env.mieru:MIERU_MITA_SHA256:mieru-manager`,
   add `PROXY_CONTROL_XRAY_ROUTER=on` where the Xray-router is installed, then
   `systemctl restart version-agent` once more.
5. Press «Проверить обновления» on the «Версии» screen. If anything is wrong, give the
   `mtproxy-panel:rollback-<date>` image the `latest` tag back and recreate the panel; the database
   has not changed since v0.10.

The MCP server on an existing install — per [docs/MCP.en.md](../MCP.en.md): a domain with an A
record, a certificate, `.env.mcp`, the secrets `secrets/mcp-token` and `secrets/mcp-panel-key`
(the key — `docker compose … exec panel python -m panel.cli api-key-create --name mcp --scope admin`),
`compose.mcp.yaml` in the overlay set. Later releases install from the «Proxy Control / панель» card.

The upstream poll can be turned off with `PROXY_CONTROL_UPSTREAM_CHECK=off`; only the catalog remains.
