# v0.14.0-beta.1 — совместное использование 443 и приёмка Naive

[English](#english) · **Русский**

Дата: 2026-09-23. Предыдущий выпуск: [v0.13.0-beta.1](v0.13.0-beta.1.md).

## Русский

### Изменения

- Необязательный `[ingress]` для `host_mode = "coexist"`: операторский Nginx bridge на loopback принимает PROXY protocol от чужого frontend и маршрутизирует исходный TLS по SNI без PROXY header на новые backend'ы. Существующие входы и их PROXY protocol не меняются. Для занятого чужим Nginx порта 8443 можно указать отдельный `panel_tls_port`.
- Проверяемый локальный архив через `scripts/install-release.sh --from-dir`. Не путать его SHA-256 с архивом предыдущего опубликованного тега.
- `skip_renewal_dry_run` — явное исключение только для уже существующего и локально валидного сертификата на время временной ошибки ACME. Выдача и продление отсутствующего/негодного сертификата, проверка trust, ключа, exact SAN и срока не обходятся. Версия исправляет проверку сертификата после применения исключения.
- Аутентифицированный Naive HTTP/2 CONNECT проверяет настоящий HTTPS-трафик к внешнему адресу вместо обращения контейнера Caddy к собственной панели через NAT; требует полезные байты и учёт закрытого туннеля. Неопределённый для HTTP/2 curl `http_connect=000` допустим только при успешной проверке вложенного WebPKI TLS и содержимого. Диагностика не раскрывает credentials.
- Регрессионные тесты и справка об установке обновлены. Миграции базы панели и изменения API/Fleet не требуются.

### Развёртывание и откат

Устанавливайте только архив этого выпуска с подтверждённым SHA-256. На хосте с чужим frontend сначала отдельно сохраните и проверьте существующие Nginx/SNI маршруты, подготовьте и протестируйте свой bridge и свободный loopback-порт панели. Установщик **не** создаёт и не откатывает bridge, не управляет пробросом Mieru на роутере. Перед изменением действующего узла сделайте согласованные копии SQLite, `secrets/`, `.env*`, Nginx и сервисов. После установки проверьте MTProto resPQ, Naive настоящим клиентом, Mieru TCP/UDP, панель, подписку и прежние Xray-маршруты. При отказе используйте транзакционный откат установщика, а для внешнего bridge — отдельную операторскую копию. Не считайте этот выпуск обновлением уже установленного узла по одному `VERSION`: пути обновления и сохранность данных проверяются отдельно.

### Фактическая приёмка

На домашнем узле локальный интеграционный архив с этими изменениями (до нового номера версии) завершил транзакцию `active` с 7/7 проверенными действиями; внешние клиенты подтвердили Naive (sing-box, HTTPS 200/204), Mieru (официальный клиент TCP и UDP, HTTP 204) и MTProxy (TDLib resPQ), TLS панели и подписок. Проброс 46001 на роутере — отдельная операторская граница. Это **не** доказательство прохождения полного одноразового релизного стенда именно для архива v0.14.0-beta.1; результаты такого стенда и публикации указываются только после выполнения.

## English

### Changes

- Opt-in `[ingress]` for coexistence with a foreign shared-443 frontend that sends PROXY protocol to all backends. An operator-owned loopback Nginx bridge consumes that header and routes unmodified TLS by SNI; existing routes retain their headers. `panel_tls_port` avoids a foreign listener on 8443.
- Verified local release bundle via `scripts/install-release.sh --from-dir`; never reuse the checksum of an older published tag.
- Explicit `skip_renewal_dry_run` only for a locally valid existing certificate during a transient ACME outage. Local trust, exact SAN, expiry and key checks remain mandatory; new or invalid certificates must still be issued/renewed. Verification now honors the exception.
- Naive acceptance uses authenticated HTTP/2 CONNECT to a public HTTPS origin rather than hairpinning through the Docker container to the host's own panel. It requires payload, a closed tunnel and accounting; curl's HTTP/2 `http_connect=000` is acceptable only when an inner WebPKI TLS request succeeds. Errors disclose no credentials.
- Regression tests and bilingual installer guidance. No panel database migration or Fleet wire change.

### Deployment and rollback

Verify this release archive and its own SHA-256. On a foreign frontend, back up and separately test the operator-owned bridge and all existing routes before installing; the installer neither creates nor rolls back that bridge or router port forwarding. Preserve a consistent SQLite backup, `secrets/`, `.env*`, Nginx and service state. Check real MTProto resPQ, Naive and Mieru TCP/UDP clients, panel, subscriptions and previous Xray routes after installation. Use transactional rollback on failure. Upgrading an existing installation requires its own data-preserving upgrade procedure, not merely replacing `VERSION`.

### Validation scope

An earlier locally patched integration archive completed on the home host (`active`, 7/7 verified actions), with external Naive (sing-box, HTTPS 200/204), official Mieru TCP/UDP (HTTP 204), MTProxy TDLib resPQ, panel and subscription TLS checks. Router forwarding is operator-owned. These results **do not** constitute a disposable-lab pass for the new v0.14.0-beta.1 archive; publish only after that archive passes the required release gates.
