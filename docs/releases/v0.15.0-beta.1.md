# v0.15.0-beta.1 — версия панели и обновления узлов из центра

[English](#english) · **Русский**

Дата: 2026-09-23. Предыдущий выпуск: [v0.14.0-beta.1](https://github.com/dubr1k/proxy-control/releases/tag/v0.14.0-beta.1).

> **Beta:** правка агента обновлений (`version_agent/`) и панели. Без миграции базы, изменения Fleet API, установщика или менеджеров протоколов. Полный список опубликованных файлов и контрольные суммы — на [странице выпуска](https://github.com/dubr1k/proxy-control/releases/tag/v0.15.0-beta.1).

## Русский

### Исправлено

- **Экран «Версии» показывает версию панели, которая работает на самом деле.** Раньше агент брал её из файла `VERSION` в каталоге проекта. Если файлы следующего выпуска попадали на хост без пересборки панели (например, каталог синхронизировался с рабочей копией), экран писал, что новый выпуск уже установлен, а кнопка «Обновить» оставалась неактивной. При этом «Обзор» и меню профиля показывали прежнюю версию. Теперь агент спрашивает работающий контейнер (`/app/VERSION`) и берёт файл, только если контейнер не отвечает. Откат после неудачного обновления тоже сверяется с версией, которая действительно работала.

### Добавлено

- **Агент сам проверяет обновления.** Раз в 6 часов агент на каждом хосте опрашивает upstream: список версий узла приходит на центр вместе с heartbeat'ом, и нажимать «Проверить обновления» на каждом узле больше не нужно. Интервал задаётся в `version-agent.env` переменной `PROXY_CONTROL_UPSTREAM_CHECK_INTERVAL` (секунды, `0` — только по запросу). Кнопки проверки остались.
- **Ресурсы сервера на «Обзоре» обновляются сами.** Карточка CPU/RAM/диска перечитывается каждые 5 секунд, пока «Обзор» открыт, а вкладка видна. В карточке видно время последнего обновления. Для этого есть лёгкий запрос `GET /api/host`: он обращается только к агенту, а не ко всем протоколам.

### Обновление с v0.12–v0.14

Из панели: «Версии» → «Проверить обновления» → карточка «Proxy Control / панель» → `0.15.0-beta.1`. Узел обновляется из центра: «Узлы» → узел → «Обновления». Агент скачивает архив выпуска, сверяет SHA-256 с `SHA256SUMS`, сохраняет копии дерева, базы и образа, пересобирает панель и при сбое откатывает всё обратно. Новый код агента начинает работать после его перезапуска, который агент выполняет сам последним шагом.

Вручную: сохраните образ панели, согласованную копию базы, `secrets/` и `.env*`; перенесите `panel/`, `version_agent/` (в каталог агента, обычно `/opt/proxy-control`), `VERSION` и документацию из проверенного архива, **не заменяя** секреты, сертификаты, `.env*` или `version-overrides/`. Затем:

```bash
docker compose --project-name mtproxy <ваши --env-file и -f> up -d --build --no-deps --wait panel
systemctl restart version-agent
docker exec proxy-control-panel cat /app/VERSION  # 0.15.0-beta.1
```

## English

### Fixed

- **The Versions screen shows the panel version that is actually running.** The agent used to read it from the project directory's `VERSION` file. When the next release's files reached a host without the panel being rebuilt (for example, a directory kept in sync with a working copy), the screen claimed the new release was installed and kept the Update button disabled, while the overview and the profile menu showed the old version. The agent now asks the running container (`/app/VERSION`) and falls back to the file only when the container does not answer. A rollback after a failed update is also verified against the version that was really running.

### Added

- **The agent checks for updates by itself.** Every 6 hours each host's agent polls upstream, so a node's version list reaches the central with its heartbeat — nobody has to press «Проверить обновления» on each node. Set the interval with `PROXY_CONTROL_UPSTREAM_CHECK_INTERVAL` in `version-agent.env` (seconds, `0` = only on request). The check buttons stay.
- **Server resources on the overview refresh themselves.** The CPU/RAM/disk card reloads every 5 seconds while the overview is open and the tab is visible, and it shows when it was last updated. It uses a light `GET /api/host` request that asks only the agent, not every protocol.

### Upgrading from v0.12–v0.14

From the panel: «Версии» → «Проверить обновления» → the «Proxy Control / панель» card → `0.15.0-beta.1`. A node is updated from the central: «Узлы» → the node → «Обновления». The agent downloads the release archive, checks its SHA-256 against `SHA256SUMS`, keeps copies of the tree, the database and the image, rebuilds the panel and rolls everything back on failure. The agent's new code takes effect after it restarts itself as the last step.

By hand: back up the panel image, a consistent database copy, `secrets/` and `.env*`; copy `panel/`, `version_agent/` (into the agent directory, usually `/opt/proxy-control`), `VERSION` and the docs from the verified archive **without replacing** secrets, certificates, `.env*` or `version-overrides/`. Then:

```bash
docker compose --project-name mtproxy <your --env-file and -f> up -d --build --no-deps --wait panel
systemctl restart version-agent
docker exec proxy-control-panel cat /app/VERSION  # 0.15.0-beta.1
```
