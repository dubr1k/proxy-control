## Исправления после 512be74

1. Передача владения после обновления охватывает код Core и version-agent.
   Оба checkpoint обновляются одной записью; чужие изменения не принимаются.
2. Изменение только `installer/` также перезапускает version-agent, чтобы
   следующий цикл не использовал закешированный модуль Python.
3. Явный `uninstall --purge-data` удаляет пустой `version-overrides`, оставленный
   обновлятором. Файлы внутри и символические ссылки сохраняются.
4. Purge удаляет три тома Unix-сокетов дополнительных менеджеров после удаления
   контейнеров. Проверяются фиксированные имена и метки Compose; `--force` и
   массовая очистка Docker не используются.

Для исправлений получены падающие регрессионные тесты и последующий успешный
прогон. Два последних дефекта обнаружены настоящей чистой установкой: старый
purge сообщал об удалении, но оставлял каталог и тома, блокирующие новый install.
Первоначальные неуспешные попытки сохранены в журнале, а не засчитаны как успех.

Установщик изменён (`installer/transaction.py`, `installer/cli.py`, Core-адаптер),
а `scripts/install-release.sh --requirements` и двуязычные инструкции описывают
переход с агентом без передачи владения. Новых конфигурационных полей нет.

## Штатное обновление и repair

Перед проверкой сохранены online-копия SQLite с `integrity_check`, secrets,
отдельная копия master key, конфигурация и код, журналы установщика, Nginx и
сертификаты. Фактические восемь образов получили rollback-теги. Консистентный
снимок пяти томов сделан при остановленных службах, затем все восемь контейнеров
восстановлены до `healthy`. Исходная резервная копия сохранена и после повторов.

## Чистая установка

Проверяется чистая установка приложения в режиме `coexist` с профилем full,
Xray-router и MCP. Существующие сертификаты и чужой frontend сохраняются;
это не переустановка ОС. После исправленного штатного purge фактически получены:

```text
installer status: uninstalled
project containers: 0
project volumes: 0
/opt/mtproxy-shared443: absent
foreign files and route bytes: unchanged
```

Финальные `plan`, `install`, health, `repair` и `report` завершились с кодом 0.
Все действия выполнены штатным CLI из того же архива, что использован для
обновления. После purge не потребовалось вручную удалять каталог или тома.
Драйвер сначала остановился на сравнении маршрутов после исключения блока.
Отдельная побайтовая проверка выполнена по сохранённой конфигурации Nginx.
Содержимое чужих маршрутов совпало с резервной копией; затем проверка продолжена
без изменения хоста или кода установщика. Исходный отказ драйвера сохранён в логе.

Повторные `plan` и `install` также завершились с кодом 0. Байты состояния
транзакции и master key не изменились: `repeat_install_idempotent: true`.
Финальная проверка снова дала восемь healthy-контейнеров и `failed_checks: 0`.
Все десять checkpoint имеют `success: true`.
