# v3.3.0 — удобство работы с клиентами и подписками

[English](#english) · **Русский**

Дата: 2026-10-25. Предыдущий выпуск: [v3.2.1](https://github.com/dubr1k/proxy-control/releases/tag/v3.2.1).

## Русский

### Что изменилось

- **Клиентов можно удалять.** Архивного клиента, у которого все доступы уже сняты с узлов, удаляет пункт «Удалить навсегда» в меню «⋯» его карточки. Пока на узле остаётся доступ или не закончена операция, панель отказывает и объясняет почему.
- **Новая страница подписки.** Ссылка `/s/{token}` стала понятной странице: кнопки «Добавить в <приложение>» для подходящих приложений, ссылки на скачивание, «Копировать ссылку подписки», QR-код по запросу, доступы по протоколам с кнопками копирования, английская версия по `?lang=en`. Клиенту только с MTProxy вместо подписки показывается ссылка Telegram.
- **«На чём клиент?»** В окне клиента и в наборе доступов сначала выбирается платформа, затем приложение. «Ротировать URL» теперь называется «Выпустить новую ссылку».
- **Список клиентов.** По умолчанию показаны активные клиенты; кнопки в карточке сокращены до «Открыть» и «Узлы и доступы», остальное — в меню «⋯». Окна с матрицей доступов шире и с легендой.
- **Обзор.** Блок «Требует внимания» собирает клиентов с проблемами, «Выдать доступ» вынесено в заголовок.
- **Узлы.** «Добавить узел» вместо «Панель»; на карточке этого сервера есть «Создать ключ для центра».
- **Окно клиента надёжнее.** Подписи кнопок не пропадают, имя учётной записи подбирается свободное, после частичного сбоя повторная попытка использует уже созданного клиента, ошибки сервера показываются по-русски.
- **Понятнее тексты.** Простые формулировки вместо жаргона и единое обозначение стрелок трафика; на экране «Версии» легенда собрана в одну плашку.

### Что важно знать

- AmneziaWG по-прежнему не входит в подписки. У Hiddify статус TrustTunnel в `GET /api/subscriptions/compatibility` теперь `pending` вместо `unverified`.
- Пароль TrustTunnel в окне доступа показывается как есть: скрывающая его маска убрана.
- Удаление клиента необратимо; перед ним клиент должен быть в архиве.
- Миграций базы и изменений конфигурации хоста нет.
- **Установщик изменился.** Мастер замечает уже установленный Proxy Control, подсказывает `bash install-release.sh --update` и по умолчанию завершается без изменений; флаг `--lang` пропускает вопрос о языке; вопросы стали короче и с подсказками, итоговый обзор читается без служебных имён. Компоненты, порты, версии и требования к хосту не менялись. Публикуемый `install-release.sh` получает версию `3.3.0` и новый SHA-256 архива, рядом лежит `install-release.sh.sha256`; формат `SHA256SUMS` из трёх файлов прежний.
- **Обновляетесь с 2.x?** Сначала прочитайте заметки [v3.0.0](https://github.com/dubr1k/proxy-control/releases/tag/v3.0.0) и [v3.0.1](https://github.com/dubr1k/proxy-control/releases/tag/v3.0.1): при переходе стек Docker переименовывается из `mtproxy` в `proxy_panel_by_dubr1k` с кратким перерывом в работе служб.

### Новая установка

Используйте Ubuntu 24.04 LTS x86-64 и обычного пользователя с `sudo`, не вход под root. Подготовьте DNS-имена и следуйте [руководству по установке](https://github.com/dubr1k/proxy-control/blob/v3.3.0/README.md#установка-человеком) и [справочнику установщика](https://github.com/dubr1k/proxy-control/blob/v3.3.0/docs/INSTALLER_REFERENCE.ru.md).

В пустом рабочем каталоге:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v3.3.0/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v3.3.0/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Продолжайте только после успешной проверки контрольной суммы.

### Обновление

Сделайте [резервную копию](https://github.com/dubr1k/proxy-control/blob/v3.3.0/docs/BACKUP_RESTORE.ru.md), скачайте и проверьте те же файлы, затем выполните:

```bash
bash install-release.sh --update
```

Можно и с экрана «Версии» → «Proxy Control / панель». Порядок обновления флота прежний: сначала узлы, центральная панель последней. Тома Docker, базу и секреты при обновлении не удаляйте. Подробнее: [обновление](https://github.com/dubr1k/proxy-control/blob/v3.3.0/docs/UPGRADING.ru.md).

## English

### What changed

- **Clients can be deleted.** An archived client whose accesses are already removed from the nodes is deleted with «Удалить навсегда» in the «⋯» menu of its card. While an access remains on a node or an operation is unfinished, the panel refuses and says why.
- **A new subscription page.** The `/s/{token}` link is now a readable page: «Добавить в <app>» buttons for fitting apps, download links, «Копировать ссылку подписки», a QR code on demand, accesses per protocol with copy buttons, and an English version via `?lang=en`. A client with MTProxy only gets a Telegram link instead of a subscription.
- **«На чём клиент?»** The client window and the access bundle ask for the platform first and then the app. «Ротировать URL» is now «Выпустить новую ссылку».
- **Client list.** Active clients are shown by default; the card keeps «Открыть» and «Узлы и доступы», the rest is in the «⋯» menu. The access-matrix windows are wider and have a legend.
- **Overview.** A «Требует внимания» block gathers clients with problems and «Выдать доступ» moves to the header.
- **Nodes.** «Добавить узел» replaces «Панель»; the card of this server has «Создать ключ для центра».
- **A more reliable client window.** Button labels no longer vanish, a free account name is proposed, a retry after a partial failure reuses the client already created, and server errors are shown in Russian.
- **Clearer wording.** Plain phrases instead of jargon and one traffic-arrow convention; the «Versions» legend is one banner.

### Good to know

- AmneziaWG is still not part of subscriptions. Hiddify's TrustTunnel status in `GET /api/subscriptions/compatibility` is now `pending` instead of `unverified`.
- The TrustTunnel password in the access window is shown as is: the masking was removed.
- Deleting a client cannot be undone; the client must be archived first.
- No database migration or host configuration change.
- **The installer changed.** The wizard notices an existing Proxy Control installation, points at `bash install-release.sh --update` and quits without changes by default; `--lang` skips the language question; the questions are shorter with hints and the final review reads without internal names. Components, ports, versions and host requirements did not change. The published `install-release.sh` is stamped with `3.3.0` and the new archive SHA-256, with `install-release.sh.sha256` alongside; the three-file `SHA256SUMS` format is unchanged.
- **Updating from 2.x?** Read the notes of [v3.0.0](https://github.com/dubr1k/proxy-control/releases/tag/v3.0.0) and [v3.0.1](https://github.com/dubr1k/proxy-control/releases/tag/v3.0.1) first: the upgrade renames the Docker stack from `mtproxy` to `proxy_panel_by_dubr1k` with a brief service interruption.

### Fresh installation

Use Ubuntu 24.04 LTS x86-64 and a regular user with `sudo`, not a root login. Prepare your DNS names and follow the [installation guide](https://github.com/dubr1k/proxy-control/blob/v3.3.0/README.en.md#installation-by-a-human) and [installer reference](https://github.com/dubr1k/proxy-control/blob/v3.3.0/docs/INSTALLER_REFERENCE.en.md).

In an empty working directory:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v3.3.0/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v3.3.0/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Continue only after checksum verification succeeds.

### Upgrading

Make a [backup](https://github.com/dubr1k/proxy-control/blob/v3.3.0/docs/BACKUP_RESTORE.en.md), download and verify the same files, then run:

```bash
bash install-release.sh --update
```

The «Versions» screen → «Proxy Control / panel» works too. The fleet update order is unchanged: nodes first, central panel last. Do not delete Docker volumes, the database or secrets as part of an update. More: [upgrading](https://github.com/dubr1k/proxy-control/blob/v3.3.0/docs/UPGRADING.md).
