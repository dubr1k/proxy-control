## Русский

### Исправлено

- **`uninstall` больше не стирает данные Docker и сертификаты.** Пакеты, которые установщик поставил сам (на чистом сервере это, например, `docker.io` и `certbot`), раньше удалялись `apt-get purge` — с `--purge-data` и без него. Purge `docker.io` удаляет `/var/lib/docker` со всеми томами, включая базу панели, а purge `certbot` — `/etc/letsencrypt` с действующими сертификатами. Теперь без `--purge-data` такие пакеты снимаются `apt-get remove`: тома, база панели и сертификаты остаются на месте. `apt-get purge` выполняется только при явном `uninstall --purge-data`. Откат неудачной установки тоже больше не делает purge. То же правило действует для узлов, поставленных прежним рантаймом `proxyctl`.
- **`uninstall` падал сразу после purge.** dpkg хранит вычищенный пакет с пустой версией, и установщик считал такой ответ испорченным: данные уже были стёрты, а удаление завершалось ошибкой. Теперь такой пакет читается как неустановленный.
- **Сообщения о возможностях узла без старых номеров версий.** Если связанный узел не поддерживает маршрутизацию, полосы и цепи, свои выходы или geodata, панель и API говорят, чего не хватает, и просят обновить панель узла. Сценарий обновления и `install-release.sh --requirements` тоже больше не ссылаются на бета-выпуски.

### Документация

- README переписан: отдельные разделы «Установка человеком» и «Установка ИИ-агентом». Второй — неинтерактивная установка для агента, которому вы дали доступ к серверу: конфигурация из примеров, план, digest подтверждаете вы, затем установка и отчёт. Там же готовый текст задания для агента.
- Документация описывает текущее поведение: история бета-выпусков удалена, журнал изменений начинается с 1.0.0, руководство по обновлению собрано заново для узлов 1.x.
- Добавлено, что включить Xray-router на узле с уже работающей установкой установщик пока не умеет: решайте, нужен ли роутер, до первой установки.

### Обновление с v1.1.1

Сделайте [резервную копию](../BACKUP_RESTORE.ru.md) и обновите сервер одной командой обычным пользователем с `sudo`:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/latest/download/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/latest/download/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh --update
```

Или в панели: «Версии» → карточка «Proxy Control / панель» → `1.1.2` → «Установить». В парке связанных панелей сначала обновите узлы, затем центр.

Исправление `uninstall` работает, когда удаление запускается из распакованного выпуска 1.1.2 и новее. Если вы собираетесь удалить установку с чистого сервера, используйте `python3 -m installer.cli uninstall` из выпуска 1.1.2, а не из более старого.

## English

### Fixed

- **`uninstall` no longer deletes Docker data and certificates.** Packages the installer installed itself (on a clean server, for example `docker.io` and `certbot`) used to be removed with `apt-get purge`, with or without `--purge-data`. Purging `docker.io` deletes `/var/lib/docker` with every volume, the panel database included, and purging `certbot` deletes `/etc/letsencrypt` with the live certificates. Without `--purge-data` such packages are now removed with `apt-get remove`: the volumes, the panel database and the certificates stay where they are. `apt-get purge` runs only on an explicit `uninstall --purge-data`. The rollback of a failed installation no longer purges either. The same rule applies to hosts installed by the earlier `proxyctl` runtime.
- **`uninstall` failed right after a purge.** dpkg keeps a purged package with an empty version, and the installer took that answer as malformed: the data was already gone and the uninstall still ended in an error. Such a package now reads as not installed.
- **Node capability messages without old version numbers.** When a linked node does not support routing, lanes and chains, custom exits or geodata, the panel and the API say what is missing and ask to update the node's panel. The update script and `install-release.sh --requirements` no longer refer to beta releases.

### Documentation

- The README is rewritten with separate «Installation by a human» and «Installation by an AI agent» sections. The second is a non-interactive installation for an agent you gave access to the server: a configuration from the examples, the plan, the digest you confirm, then the installation and a report. It includes a ready task text for the agent.
- The documentation describes the current behaviour: the beta-release history is removed, the changelog starts at 1.0.0, and the upgrade guide is rebuilt for 1.x hosts.
- It now states that the installer cannot add the Xray-router to a running installation yet: decide whether you need the router before the first installation.

### Upgrading from v1.1.1

Make a [backup](../BACKUP_RESTORE.en.md) and update the server with one command as a regular user with `sudo`:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/latest/download/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/latest/download/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh --update
```

Or in the panel: Versions → the «Proxy Control / панель» card → `1.1.2` → Install. In a fleet of linked panels, update the nodes first, then the central panel.

The `uninstall` fix applies when the uninstall runs from an extracted 1.1.2 release or newer. To remove an installation from a clean server, run `python3 -m installer.cli uninstall` from the 1.1.2 release, not from an older one.
