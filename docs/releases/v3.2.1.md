# v3.2.1 — выбор узла на экранах AmneziaWG и TrustTunnel

[English](#english) · **Русский**

Дата: 2026-10-23. Предыдущий выпуск: [v3.2.0](https://github.com/dubr1k/proxy-control/releases/tag/v3.2.0).

## Русский

### Что изменилось

- **Выбор узла при выдаче доступа.** Окна создания доступа на экранах AmneziaWG и TrustTunnel загружают актуальный список узлов при каждом открытии: больше не нужно сначала заходить на другой экран. TrustTunnel создаёт доступ на выбранном узле, а не всегда на локальном. В AmneziaWG доступные версии соответствуют сведениям выбранного узла.
- **Пустые списки читаются нормально.** На обоих экранах заголовок и пояснение пустого списка оформлены отдельными строками, как в остальных разделах панели.
- **Подписка NekoBox.** Вариант sing-box для NekoBox несёт NaiveProxy, Mieru и TrustTunnel вместе. TrustTunnel использует HTTP/2 поверх TCP, QUIC выключен. Добавлены английские переводы пояснений о составе подписки и неподдерживаемых протоколах.
- **Обновление зависимостей.** В панели и MCP-сервере `certifi` обновлён до `2026.10.19`, `opentelemetry-api` — до `1.45.1`: устранены замечания аудита `PYSEC-2026-4320` и `CVE-2026-114603`.

### Что важно знать

- Поддержка TrustTunnel в NekoBox/NyameBox зависит от сборки приложения; проверка в самом приложении не заявляется. MTProxy и Mieru с диапазоном портов остаются в `unsupported`. Вариант NekoBox не предназначен для официального sing-box: тот не поддерживает исходящий TrustTunnel.
- API, формат обмена между панелями, миграции базы и конфигурация хоста не меняются. Выбор узла использует существующие возможности флота; нужный протокол должен быть доступен на выбранном узле.
- **Установщик:** исходники и поведение установщика не менялись. При сборке выпуска публикуемый `install-release.sh` получает версию `3.2.1` и новый SHA-256 архива; рядом генерируется `install-release.sh.sha256`. Набор файлов выпуска и формат `SHA256SUMS`, проверяющего три файла — архив, `release-manifest.json` и `sbom.spdx.json`, — остаются прежними.
- **Обновляетесь с 2.x?** Сначала прочитайте заметки [v3.0.0](https://github.com/dubr1k/proxy-control/releases/tag/v3.0.0) и [v3.0.1](https://github.com/dubr1k/proxy-control/releases/tag/v3.0.1): при переходе стек Docker переименовывается из `mtproxy` в `proxy_panel_by_dubr1k` с кратким перерывом в работе служб.

### Новая установка

Используйте Ubuntu 24.04 LTS x86-64 и обычного пользователя с `sudo`, не вход под root. Подготовьте DNS-имена и следуйте [руководству по установке](https://github.com/dubr1k/proxy-control/blob/v3.2.1/README.md#установка-человеком) и [справочнику установщика](https://github.com/dubr1k/proxy-control/blob/v3.2.1/docs/INSTALLER_REFERENCE.ru.md).

В пустом рабочем каталоге:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v3.2.1/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v3.2.1/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Продолжайте только после успешной проверки контрольной суммы.

### Обновление

Сделайте [резервную копию](https://github.com/dubr1k/proxy-control/blob/v3.2.1/docs/BACKUP_RESTORE.ru.md), скачайте и проверьте те же файлы, затем выполните:

```bash
bash install-release.sh --update
```

Можно и с экрана «Версии» → «Proxy Control / панель». Порядок обновления флота прежний: сначала узлы, центральная панель последней. Тома Docker, базу и секреты при обновлении не удаляйте. Подробнее: [обновление](https://github.com/dubr1k/proxy-control/blob/v3.2.1/docs/UPGRADING.ru.md).

## English

### What changed

- **Node selection when issuing an access.** The access dialogs on the AmneziaWG and TrustTunnel screens load the current node list every time they open: there is no need to visit another screen first. TrustTunnel creates the access on the selected node rather than always on the local node. AmneziaWG offers the versions reported by the selected node.
- **Readable empty lists.** On both screens the empty-list heading and explanation appear on separate lines, matching the rest of the panel.
- **NekoBox subscription.** The NekoBox sing-box variant carries NaiveProxy, Mieru and TrustTunnel together. TrustTunnel uses HTTP/2 over TCP with QUIC off. The descriptions of included and unsupported protocols now have English translations.
- **Dependency updates.** The panel and MCP server update `certifi` to `2026.10.19` and `opentelemetry-api` to `1.45.1`, addressing dependency-audit findings `PYSEC-2026-4320` and `CVE-2026-114603`.

### Good to know

- TrustTunnel support in NekoBox/NyameBox depends on the app build; verification in the app itself is not claimed. MTProxy and Mieru with port ranges remain in `unsupported`. The NekoBox variant is not for official sing-box, which has no TrustTunnel outbound.
- No API, panel-to-panel wire format, database migration or host configuration change. Node selection uses the existing fleet capabilities; the selected node must provide the required protocol.
- **Installer:** installer source and behavior are unchanged. The release build stamps the published `install-release.sh` with version `3.2.1` and the new archive SHA-256 and generates `install-release.sh.sha256` alongside it. The release asset set and the `SHA256SUMS` format, covering three files — the archive, `release-manifest.json` and `sbom.spdx.json` — stay unchanged.
- **Updating from 2.x?** Read the notes of [v3.0.0](https://github.com/dubr1k/proxy-control/releases/tag/v3.0.0) and [v3.0.1](https://github.com/dubr1k/proxy-control/releases/tag/v3.0.1) first: the upgrade renames the Docker stack from `mtproxy` to `proxy_panel_by_dubr1k` with a brief service interruption.

### Fresh installation

Use Ubuntu 24.04 LTS x86-64 and a regular user with `sudo`, not a root login. Prepare your DNS names and follow the [installation guide](https://github.com/dubr1k/proxy-control/blob/v3.2.1/README.en.md#installation-by-a-human) and [installer reference](https://github.com/dubr1k/proxy-control/blob/v3.2.1/docs/INSTALLER_REFERENCE.en.md).

In an empty working directory:

```bash
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v3.2.1/install-release.sh
curl -fsSLO https://github.com/dubr1k/proxy-control/releases/download/v3.2.1/install-release.sh.sha256
sha256sum --check install-release.sh.sha256
bash install-release.sh
```

Continue only after checksum verification succeeds.

### Upgrading

Make a [backup](https://github.com/dubr1k/proxy-control/blob/v3.2.1/docs/BACKUP_RESTORE.en.md), download and verify the same files, then run:

```bash
bash install-release.sh --update
```

The «Versions» screen → «Proxy Control / panel» works too. The fleet update order is unchanged: nodes first, central panel last. Do not delete Docker volumes, the database or secrets as part of an update. More: [upgrading](https://github.com/dubr1k/proxy-control/blob/v3.2.1/docs/UPGRADING.md).
