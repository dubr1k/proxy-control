### Следующие улучшения за пределами исправлений

1. Согласовать журнал установщика с обновлением через version-agent. На ams-test журнал всё ещё относится к v1.1.0, а 33 изменённых управляемых файла на момент диагностики точно совпадали с штатно развёрнутым архивом rc.1. Секреты, env и Nginx не изменены. По коду старый checkpoint не принимает эти хеши при repair; такой repair не запускался, журнал не переписывался. Нативная приёмка обновления использует штатный update-host и отдельную проверку совпадения с архивом; это не доказательство работоспособности repair старого поколения после обновления.
2. Добавить отдельную readiness-диагностику с состоянием БД, возрастом последнего reconcile и незавершёнными операциями. HTTP health и Docker healthy сами по себе не подтверждают применение всех доступов.
3. Измерить работу парка на реалистичном числе узлов: длительность цикла, долю повторов, задержку применения и предел очереди. Текущие 8 параллельных отправок — ограничение ресурсов, а не доказанная оптимальная настройка для любого парка.
4. Расширить реальные клиентские проверки 3x-ui: установка и проверка слушателей не доказывают работу VLESS TCP, XHTTP и Hysteria2. Отдельно остаётся ручная приёмка Telegram реальным пользовательским клиентом.
5. Для рабочих coexist-конфигураций отдельно спроектировать доверенную передачу исходного IP с владельцем фронтенда. Автоматическое изменение чужих SNI ради этого исправления не выполнялось.
6. Постепенно разделить крупные installer/core и routing/service по существующим границам ownership, journal и rollback; сначала сохранить контрактные тесты. Для этого не требуется переписывать установщик целиком.
