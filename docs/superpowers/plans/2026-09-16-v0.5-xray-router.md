# v0.5 Xray Router Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** необязательный выделенный Xray egress-router на узле: оператор подключает к нему NaiveProxy и/или Mieru, задаёт политику с `geosite/geoip/port/block рядом с WARP`, применяет её транзакционно локально и с центральной панели; узлы без роутера работают как в v0.4. Плюс финализация vNext: backup/restore, матрица негативных тестов, гейт на `ams-test`, релизная последовательность.

**Architecture:** закреплённый артефакт Xray в каталоге релиза → контейнер `proxy-control-xray-router` (host network, менеджер-супервизор Python поверх дочернего `xray`, UDS API `get/plan/apply/rollback` per service) → два аутентифицированных SOCKS5-ingress на loopback (`naive` 45101, `mieru` 45102) → нативные менеджеры получают провайдер `router` (Caddy `upstream socks5://u:p@…`, mita `socks5Authentication`) → панель: backend `xray_router` в политике, компилятор в `XrayRoutingIntent`, attach/detach как явные действия, поколения Fleet v2 с `companion`-документом → UI.

**Tech Stack:** Python 3.12/3.13, FastAPI, pydantic 2, SQLite/WAL, httpx, `http.server` на UDS, Xray-core 26.3.27 (`Xray-linux-64.zip`), Caddy 2.11.4 + forwardproxy `d62c80d`, mita 3.36, vanilla JS, pytest; гейт только на `ams-test` через `scripts/dev/remote-gate.sh`.

**Spec:** `docs/superpowers/specs/2026-09-16-v0.5-xray-router-design.md` (+ спека vNext Phase 7–8, ADR 006, ADR 007).

## Global Constraints

- Ветка `feature/vnext-v0.5-xray-router` от `eb20e8d`; коммиты без трейлеров `Co-Authored-By`/`Claude-Session` (правило владельца).
- Каждый тест/гейт — только на `ams-test` (`remote-gate.sh quick|full|compose|lab-host|fleet|routing|router`); macOS не авторитетен. `AMS_Z` — только живая проверка в Task 15 после зелёного гейта (владелец 2026-09-16); пользователи `AMS_Z` не трогаются, хост возвращается в исходное состояние (кроме версии панели/менеджеров).
- Миграции только additive, продолжают `MIGRATIONS` с версии 14 → `ROUTING_V15`; frozen identifiers `docs/COMPATIBILITY.md` v0.1–v0.4 не меняются; новые (спека §5) замораживаются в этой версии.
- Секреты: ключи ingress (`user:password`) живут только в `secrets/xray-router-ingress-*`, Docker secrets, Caddyfile/mita-конфиге и поколениях роутера (`0600`); никогда — в API, DB, audit, identity/observed, `diff`, `raw`, логах.
- Лимиты v0.4 сохраняются: ≤ 128 правил, ≤ 64 селекторов каждого вида, ≤ 32 портов, compiled ≤ 16 KiB на протокол, push ≤ 64 KiB.
- MTProxy/Telemt — вне маршрутизации; per-grant — `unsupported`; UDP через роутер — `unsupported`; 3x-ui не трогается.
- Fail-closed: недостижимый провайдер → отказ; bypass `geoip:private → block` первым правилом каждого ingress; никакого молчаливого `direct`.
- Артефакт Xray оператор кладёт в `/var/lib/proxy-control/` заранее; установщик и менеджер ничего не скачивают.
- Документация двуязычная там, где пара `*.en.md`/`*.ru.md` уже есть.
