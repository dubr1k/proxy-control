## Центральная панель (fleet_v2 central)

- [T9] `NodeRejected` (429/5xx от узла) переводит связь в `offline` → отличать «узел отверг запрос» от
  «узел недоступен»: 429/5xx = backoff без `offline`/`node.down`.
- [T9] Гонка эскроу поколений N и N+1: поздний ответ на N может переписать эскроу N+1 (renderer не
  страдает — активная версия выбирается по состоянию) → сравнивать поколение отчёта с последним push перед
  `escrow_returned_credential`.
- [T10] Две версии `active` после эскроу устаревшего ответа — то же исправление, что гонка выше.
- [re-review] `escrow_returned_credential` переписывает активную версию при каждом push/poll даже при
  неизменном plaintext → пропускать запись при равенстве plaintext (гигиена журнала `secret_versions`).
- [T9] Миграция 12 не покрыта тестом с существующими строками (SQL корректен, production-хостов со строками
  нет) → unit-тест миграции на непустой таблице.
- [T8] Проглоченная ошибка при отвязке теряет класс исключения → писать класс в `detail` события
  `node.unlink`.
- [T8] Heartbeat JSON без ограничения размера → cap на тело ответа узла (как у `observed`).
- [T8] Два флага `disabled` (связь/узел) в модели → один источник истины.
- [T11] `set_disabled` в CLI зависит от `self.links` → безусловно.
- [T11] `SecretError` при обновлении связи не отображён в HTTP → 409 с кодом.
- [T11] Probe при паузе связи всё равно делает push → probe на приостановленной связи должен быть
  «сухим».
- [T11] Нет теста на самопривязку (центр добавляет сам себя) → тест (поведение верное: 409).
- [re-review, I4] «Мёртвый узел»: provisioned-грант в `deleted/pending` навсегда блокирует
  `DELETE /api/nodes/{id}` (409) → owner-override (`?force=1` с аудитом) или описанный DB-выход в
  OPERATIONS.
- [re-review] `ManagedStore.unlink()` считает `missing`-строки в `released` (косметика).
- [fix wave, I2] Одна `list_users` на каждый существующий MTProxy-ресурс за push/poll
  (`TelemtClient.current_access`) → per-apply кэш инвентаря, когда пользователей станут сотни.
- [round 3, N4] Узел `converged`, но кред Telemt так и не захватывается (capture каждый раз по таймауту или
  живой пользователь без `tls`-ссылки → `null`): центр повторяет PUT того же поколения каждый тик (15 с) без
  backoff и без видимой оператору причины (на узле — audit `fleet.generation.accept` и полный reconcile на
  каждый тик, на центре — WARNING; операция висит в `pending_remote`, шаг `remote`, `error: null`) → `_defer`
  после N удержанных absorb и/или текст ошибки шага «credential not captured yet».
- [round 3, N4] `nodes.js` показывает «есть недоставленные изменения» по `config_dirty`, хотя узел поколение
  применил и не хватает только креда; спека §5 («`converged` → `config_dirty=0`») теперь верна лишь когда все
  креды заэскроулены → уточнить формулировки UI и спеки.
- [round 3] `subscriptions/renderers/base.py::resolve_artifacts` отдаёт plaintext версии в состоянии `pending`
  (подписка показывает «голый» секрет Telemt, пока capture не состоялся; `effective_enabled` смотрит только
  `desired_state`, `SecretStore.reveal` отказывает только `revoked`) → гейт `state='active'` (одна строка).
- [round 3] Импортированные Telemt-гранты (`secret_ref is None`) никогда не попадают в `_capture_pending` —
  полагаются только на in-band capture из ответа на push; 202 на их поколении оставляет их без креда до
  следующего re-PUT.
