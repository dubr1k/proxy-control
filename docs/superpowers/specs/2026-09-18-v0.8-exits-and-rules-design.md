# v0.8 — «Выходы и правила»: маршрутизация в духе 3x-ui поверх Xray-router

Статус: **утверждено и реализовано** (2026-09-18). Решения владельца по вопросам §12:
geodata — источник Loyalsoldier с автообновлением **и** свои URL в UI (не «только с релизом»);
пресеты — торренты, реклама, RU напрямую; **WireGuard не нужен**. Реализация: ниже §1–§10 как

geodata живёт в `<state>/geodata`, автоимпорт узлов и одношаговые клиенты — тем же выпуском.

Статус на момент написания: черновик на утверждение владельцу (2026-09-18). Предыдущие выпуски:
[v0.4 routing](2026-09-14-v0.4-routing-design.md), [v0.5 Xray-router](2026-09-16-v0.5-xray-router-design.md),

DNS, reverse и сырой JSON — не сейчас.

## 1. Цель

Оператор 3x-ui привык к двум вещам: **список аутбаундов**, куда можно добавить любой сервер
(вставил `vless://…` — получил выход), и **таблица правил**, где каждая строка говорит «что →
куда» и правится в модалке. У нас выходов два вида — WARP и цепи через узлы парка, — а правила
рисуются карточками с шестью полями подряд, без обзора. v0.8 закрывает разрыв, не ломая модель:

- **Свои выходы** (`outbound:<id>`) — socks5, http(s), VLESS (TCP/WS/gRPC/XHTTP, TLS/Reality),
  Trojan, Shadowsocks, WireGuard: добавляются формой или импортом ссылки, живут **на узле**
  (в его Xray-router), проверяются кнопкой «Проверить выход» (IP, страна, задержка).
- **Таблица правил**: одна строка на правило — порядок, вкл, «что» (домены/geosite, IP/geoip,
  порты, протокол сниффинга), «куда» (выход), заметка; перетаскивание; редактирование в модалке
  с подсказчиком кодов geodata **того узла**.
- **Быстрые настройки**: переключатели, которые материализуются обычными правилами с меткой
  `preset`: торренты → блок, реклама → блок, приватные сети (уже всегда блок — показываем как
  факт), «российские домены напрямую» и т. п. — набор кодов проверяется на стенде по
  фактическому `geosite.dat`.
- **Geodata на виду**: экран показывает, откуда списки, какой версии и когда обновлялись.

Всё это — только для сервисов, **подключённых к Xray-router** узла: нативные backend'ы
(Caddy, mita) остаются как есть, предпросмотр честно отвечает `egress_unsupported`.

### Не входит в v0.8

Балансировщики, DNS-вкладка, reverse, произвольный JSON аутбаунда, mux/sockopt сверх базовых,
UDP (mita остаётся напрямую), выходы для MTProxy, автообновление geodata без пина (см. §7).

## 2. Словарь

| Термин | Что это |
| --- | --- |
| Выход (exit) | Куда Xray-router отправляет поток: `direct`, `block`, `warp`, `node:<цепь>`, **`outbound:<id>`** |
| Свой выход (custom outbound) | Запись `egress_outbounds` панели: протокол, адрес, транспорт, секрет в escrow |
| Правило | Как в v0.4–v0.7: селекторы + действие + выход, first-match; **новое** — селектор `protocols` (`http`, `tls`, `quic`, `bittorrent` — сниффинг Xray) и метка `preset` |
| Пресет | Правило, которое создал переключатель «Быстрых настроек»; правится и удаляется как обычное, переключатель отражает его наличие |
| Geodata | `geosite.dat`/`geoip.dat` узла: файлы из архива Xray-core, закреплённого установщиком (§7) |

## 3. Архитектурные решения

1. **Выходы принадлежат узлу, а не панели.** Аутбаунд — это конфигурация Xray конкретного узла;
   в базе он привязан к `node_id`, на связанную панель едет поколением fleet v2 (ресурс
   `egress_outbound`), в локальный роутер — документом intent. Центр видит выходы всех узлов и
   правит их, как правит политики.
2. **Секреты — в escrow, как у relay-учёток.** UUID/пароль/приватный ключ WireGuard лежат в
   `secrets_store` (`purpose = exit.credential`), API чтения отдаёт только `has_secret: true`,
   импорт ссылки не пишется в журнал целиком (только протокол и хост). Поколение узла несёт
   секрет один раз, для этого узла (тот же механизм, что `relay-account`).
3. **Один парсер ссылок — на панели, на Python.** `vless://`, `trojan://`, `ss://` (обе формы
   base64), `socks://`, `http(s)://`, `wireguard://` → нормализованная запись; JS только
   отправляет строку. Так одна реализация, одни тесты, и ссылка не остаётся в браузере.
4. **IR остаётся нейтральным.** `egress: outbound:<id>` — ссылка по id; компилятор резолвит id
   в определение и отказывает кодами `exit_unknown`, `exit_disabled`, `exit_other_node`,
   `exit_secret_pending`, `egress_unsupported` (нативный backend). Схема intent роутера — **3**:
   документ несёт `outbounds: {tag: <xray outbound без секрета>}` и `credentials` отдельно (как
   relay); менеджер собирает объект Xray сам, панель никогда не шлёт сырой JSON Xray.
5. **Проверка выхода — на узле, изолированно.** Менеджер роутера поднимает временный `xray` с
   одним socks-входом на loopback и этим аутбаундом, делает `GET https://www.cloudflare.com/cdn-cgi/trace`
   с таймаутом 8 с, возвращает `ip`, `colo`, `latency_ms`; рабочий роутер не трогается.
   Один тест в момент времени на узел; результат кешируется 60 с.
6. **Пресеты — это правила.** Никакой второй модели: переключатель ищет правило с `preset: <код>`;
   включение добавляет правило **в начало** списка (блокировки) или **в конец** (направления),
   выключение удаляет его. Пользователь может отредактировать пресетное правило — тогда метка
   снимается и переключатель гаснет.
7. **Таблица не меняет API политики** — только экран и три новых поля (`protocols`, `preset`,
   `note` уже есть). Совместимость: политика v0.7 читается без миграции; `compiler_version = 3`.

## 4. Модель и API панели

### 4.1 База (миграция 17)

```text
egress_outbounds(id TEXT PK, node_id, name ≤ 48, protocol ∈ {socks, http, vless, trojan,
  shadowsocks, wireguard}, settings_json (адрес, порт, транспорт, tls/reality, flow, метод ss,
  публичный ключ, allowed_ips…), secret_id NULL, enabled, revision, created_at, updated_at,
  last_test_json NULL)
routing_rules: + protocols_json (≤ 4), + preset TEXT NULL
```

Лимиты: ≤ 16 выходов на узел, документ intent ≤ 32 КиБ, имя выхода уникально на узле,
приватные адреса выхода — только с `allow_private_address` (как у связи с панелью).

### 4.2 Эндпоинты

```text
GET    /api/routing/exits?node=<id>              список выходов узла (без секретов, с last_test)
POST   /api/routing/exits                        {node_id, name, protocol, settings, secret}
POST   /api/routing/exits/import                 {node_id, name?, link}  → как выше, из ссылки
PUT    /api/routing/exits/{id}                   правка (секрет — только если прислан)
POST   /api/routing/exits/{id}/{enable|disable|delete}
POST   /api/routing/exits/{id}/test              → {ok, ip, colo, latency_ms | error}
GET    /api/routing/geodata?node=<id>            {geosite: {sha, size, codes[]}, geoip: {...}, source}
```

Удаление выхода, на который ссылается правило или `default_egress`, — 409 `exit_in_use` с
перечнем (узел, протокол, полоса, номер правила), как у 3x-ui «deletion impact».
Всё — owner/admin, аудит: `routing.exit.create|update|delete|test`.

### 4.3 Компилятор и предпросмотр

Выход `outbound:<id>` компилируется только под `xray_router`; предпросмотр показывает строку
«выход: <имя> · vless · host:port · проверен 12 мин назад, 84 мс» или причину отказа.
Изменение выхода (адрес, секрет) делает грязными все политики узла, которые его используют, —
карточки показывают «есть неприменённые изменения», `apply` пересобирает поколение.

## 5. Xray-router (`xray_router_manager`)

- Intent схемы 3: `outbounds` + `credentials`; рендер — `{"tag": "exit-<id>", "protocol": …,
  "settings": …, "streamSettings": …}` по таблице протоколов; `sniffing` уже включён на входах,
  поэтому селектор `protocols` рендерится в `"protocol": [...]` правила.
- `POST /v1/exits/test` — §3.5; `GET /v1/geodata` — sha256 и коды (`xray` умеет перечислять?
  нет — коды читаются из `.dat` protobuf'ом менеджера, кэш по sha).
- Капабилити `custom_exits`, `protocol_match`, `geodata_codes` — панель показывает кнопки только
  узлам, которые их назвали.

## 6. Экран «Маршрутизация» (замена редактора карточек)

```text
┌ Узел ▾  | MTProxy | NaiveProxy | Mieru ┐        (как сейчас)
│ Сервис · Xray-router · применено rev 7 │
│ [Правила] [Выходы] [Быстрые настройки] [Проверка] │   ← вкладки внутри карточки
Правила:
│ #  вкл  Что                                   Куда          Заметка        ⋮ │
│ 1  ☑   geosite:category-ads-all               ⛔ блок        реклама (пресет)│
│ 2  ☑   *.youtube.com, geosite:youtube · 443   → WARP                        │
│ 3  ☑   geoip:ru, geosite:category-gov-ru      напрямую                      │
│ +Правило   Импорт/экспорт JSON   Сбросить   Сохранить   │ Предпросмотр справа
Выходы (узла):
│ имя         протокол   адрес:порт        состояние        последняя проверка   │
│ warp        socks      127.0.0.1:45000   провайдер узла   —                    │
│ nl-vless    vless      nl.example:443    ✓ включён        84 мс · NL · 1 мин   │
│ +Выход  +Из ссылки                                                          │
Быстрые настройки:
│ ○ Торренты → блок   ○ Реклама → блок   ● Приватные сети → блок (всегда)   ○ RU напрямую │
Проверка: «Куда пойдёт…» (как сейчас) + бейдж geodata: geosite <дата> · geoip <дата> · из Xray 26.3.27
```

Модалка правила: вкл · заметка · **Что**: домены/geosite (чипсы, подсказчик кодов узла), IP/geoip
(чипсы), порты, протокол (мультиселект http/tls/quic/bittorrent) · **Куда**: выход (список:
напрямую, блок, WARP, цепи, свои выходы). Модалка выхода: протокол → поля протокола (адрес,
порт, uuid/пароль, transport, security, sni, fingerprint, publicKey/shortId, flow, метод ss,
ключи WireGuard), вкладка «Ссылка» для импорта; кнопка «Проверить» доступна после сохранения.
Мобильная раскладка — карточки вместо таблицы (как `RuleCardList` в 3x-ui).

Что переносится из 3x-ui и что нет: переносятся форма аутбаунда по протоколу, импорт ссылки,
таблица с drag, модалка правила, «impact» при удалении, тестер маршрута, пресеты «Basic Routing»;
не переносятся inbound-теги (у нас вход = сервис/полоса, он выбран вкладкой), балансировщики,
`sourceIP`/`user` (полосы решают это лучше), JSON-редактор.

## 7. Geodata: откуда, как обновляются

Сегодня: `geosite.dat` и `geoip.dat` — **члены архива Xray-core v26.3.27**, закреплённые sha256
в `installer/adapters/xray_router.py` и `release/external-artifacts.json`, распакованные в
`/usr/local/lib/proxy-control/xray-router`; менеджер проверяет sha при старте. **Автообновления
нет**: списки меняются только с новым пином в релизе Proxy Control. Это соответствует принципу
«ничего незакреплённого с сети» и это надо **сказать в UI** (бейдж на экране).

v0.8 добавляет: показ версий (sha, размер, дата релиза Xray, число кодов) и подсказчик кодов
по фактическому файлу узла. Обновление списков отдельно от релиза — **вопрос владельцу**:
(а) оставить «только с релизом»; (б) второй пин `geodata` в каталоге версий (version-agent)
с проверкой sha и кнопкой «Обновить geodata» на узле. Рекомендация — (б) в v0.9, не в v0.8.

## 8. Fleet v2

Ресурс `egress_outbound` в поколении (как `relay`): `{id, tag, protocol, settings}` + секрет в
`credentials`; узел применяет его в intent своего роутера; отчёт узла подтверждает `applied`
per outbound. Центр редактирует выходы узла так же, как политики (`pending` до heartbeat).
Тест выхода на связанной панели — команда через тот же канал (`POST …/test` на узле от имени
центра ключом node-sync).

## 9. Безопасность

Секреты выходов — escrow, `no-store` на ответах с секретом (только момент импорта/создания
их не возвращает вовсе), доставка только на свой узел; ссылка импорта не логируется; тест
выхода — изолированный `xray` без доступа к рабочим входам; приватные адреса выхода — только с
явным флагом; лимиты на число выходов и размер документа; аудит всех действий.

## 10. Лаборатория и гейт

- Юнит: парсер ссылок (все шесть схем, base64-варианты ss, edge-cases), модель и лимиты,
  компилятор (`exit_*` коды, `egress_unsupported` на нативном backend), рендер (объект Xray на
  каждый протокол против фикстур), пресеты (включение/выключение/редактирование), geodata-кэш.
- Tier `router`: свой выход `socks` на `socks5-stub.py` — трафик уходит через него; тест выхода
  возвращает IP заглушки; выключение выхода → правило падает в `exit_disabled`.
- Tier `chains`/`fleet`: выход на связанной панели доставляется поколением, отчёт подтверждает.
- Tier `ui`: таблица правил (создать, перетащить, отредактировать, удалить), модалка выхода,
  импорт ссылки, пресет включает/выключает правило, бейдж geodata виден.
- Живая проверка AMS_Z → ams-test: выход VLESS на relay ams-test, выход socks на WARP AMS_Z,
  пресет «реклама → блок», тест выхода.
